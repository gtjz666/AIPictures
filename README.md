# AIPictures

Windows 独立本地 AI 图像创作桌面软件，第一阶段。Python + PySide6，ComfyUI API 推理。

代码仓库：https://github.com/gtjz666/AIPictures

当前界面采用类似 Codex 客户端的浅色两栏布局：浅灰按钮侧栏、白色预览与聊天工作区、黑色生成按钮。左侧“角色与生成 / 模型与画面 / 采样与 LoRA / 连接与显存”点击打开可复用的小窗口，修改立即用于下一次生成。正向与反向提示词并排置于右侧，反向词也会进入行走动画每帧的工作流。文件记录、骨骼预览、高级工作流和日志通过按钮按需打开。

完整操作步骤、行走 GIF 实现逻辑与网站对照见 [使用说明](docs/USAGE.md)。生成结果默认作为本地缓存，只有点“另存为 / 导出动画”才选择保存地址；“生成记录与缓存…”可分别清除选中或全部图片/动画缓存，“已保存文件”登记主动保存的文件。清理跳过运行/排队任务并保留外部已保存结果。缓存清理不触及 ComfyUI 的独立输出目录。

## 人物行走动画与透明输出

左侧“角色与生成…”小窗口中的“生成类型”选择 **单张图片** 或 **人物行走动画帧**，不再要求手动选择生成技术路线。动作词会在输入框旁显示识别结果：支持站立、伸手、行走、朝左/右、慢速/快速等中文词与部分英文动作词，处理“不要走路”等否定。词表内的中文转为英文模型条件，未识别的中文会明确提示；这不是通用翻译或多轮语言模型。

当前行走使用蓝发侧视基准，支持 8 / 16 帧。测试输入：`人物原地向右走路，侧视，全身，保持一致`。循环骨骼包括接触、承重、经过、前摆，左右腿错半周期，保持骨长和支撑脚地面线，手臂反向摆动。参考 [FrameRonin](https://frameronin.com/) 的一图动作、横版人物与序列帧交互；其[公开前端](https://github.com/systemchester/FrameRonin/blob/main/frontend/src/components/NanobananaFullChar.tsx)未提供可直接复用的骨骼坐标，本项目按角色独立构建，未复制其模型或内部工作流。

为降低身份漂移，采用**人工参考图分层预变形 + ControlNet + IP-Adapter 逐帧 AI 肢体修复**。每帧真实提交本地 ComfyUI，固定参考、种子、画幅、地面线，头身和鞋尽量保留源像素。它是固定角色的混合动画首版，当前仍有分层接缝、遮挡估计和机械感，尚不等于通用角色绑定或成熟动画模型。只校准这张角色基准，替换其他参考图时会阻止行走生成并说明原因。奔跑、跳跃等暂未实现周期，不会伪装成行走生成。

右侧预览区包含 **画面 / 动画播放、全部动画帧、精灵图** 三页；支持循环播放、暂停、逐帧滑动、点击帧单独查看。生成完成后，“导出动画…”打包透明 PNG 序列、4 列 Sprite Sheet、GIF 和可移植播放参数。PNG / 精灵图使用原始 768×1024 帧，GIF 预览为 384×512；GIF 使用二值透明，PNG 保留边缘透明通道。通过“生成记录与缓存… → 动画缓存”重新打开结果。

默认输出主体透明图，背景 Alpha 为 0，棋盘格只属于预览画布，不写入图片。单张图像在真实生成后，使用本地 CPU IS-Net 模型分离主体，保留未抠图的 `original_000.png`。`setup.bat` 安装依赖并下载一次约 179 MB 的公开去背景权重，之后离线处理；不会调用云端抠图服务。自动分割可能漏掉细小饰物或复杂主体，需检查边缘；原图始终保留，便于后续修正。

动画保存在 `data/animations/<任务>/`，包括 `sequence.json`、每帧骨骼、条件图、预变形图、透明遮罩、真实 API 工作流、ComfyUI 任务 ID 和原始 AI 输出。取消后保留已完成帧，失败不会写成完成；与单张图像共用串行任务队列。模型和本地图片均由 `.gitignore` 排除。

测试方法与本阶段验收：

```powershell
& .\.venv\Scripts\python.exe -m unittest discover -s tests -p 'test_*.py'
& .\.venv\Scripts\python.exe -m tests.live_walk
& .\.venv\Scripts\python.exe -m tests.live_animation_preview
& .\.venv\Scripts\python.exe -m tests.live_transparency
```

`live_walk` 实际生成八帧并核对八个独立 ComfyUI 任务、有效进度、逐帧落盘、循环播放和拖动预览；`live_animation_preview` 复用其结果检查全部帧、精灵图视图及 PNG/GIF 透明像素；`live_transparency` 实际生成单张角色图，检查透明输出、非空主体和原图备份。记录位于 `data/walk-acceptance.json` 和 `data/transparency-acceptance.json`。前两项需已安装角色和姿态权重，单图需先安装去背景模型。

**手动骨骼编辑尚未制作。** 可按“选帧 → 拖关节 → 保存该帧 pose.json → 重画 OpenPose / 预变形参考 → 更新该帧 LoadImage 与采样提示 → 仅重生成该帧 → 重新打包预览”实现；移动关键帧后可对相邻姿态插值并检查骨长、地面线。编辑的是每帧数据与独立工作流副本，不修改原 ComfyUI 工作流。实施前仍需用户决定。

## 蓝发侧视角色基准 v3

本机已将提供的 1086×1448 参考图保存为独立角色基准，画布为 768×1024、面朝右、地面线 y=978。启动会恢复该角色配置，也可在“角色与生成…”中点“应用这张角色基准”。角色特征提示词会固定保留，聊天框只需输入补充要求；留空也能按基准生成。

- **参考角色重绘**：SDXL + IP-Adapter PLUS + CLIP Vision，结合参考图编码与 0.30 重绘幅度。使用分块 VAE 编解码降低峰值显存，已实际生成 768×1024 图片。普通重绘不能保证精确身份、衣饰或线稿不变。
- **骨骼约束**：独立 OpenPose 条件输入 + ControlNet + 同一角色参考分支。2026-10-27 已确认当前 Comfy Desktop 能识别 `controlnet-openpose-sdxl-1.0-xinsir.safetensors`；站立/伸手工作流已导入，站立已完成 768×1024 真实出图，伸手仅完成结构及依赖校验。袜子、鞋型等角色细节仍会漂移，尚未达到固定角色序列帧验收标准。
- **骨骼预设**：站立基准和向前伸手草案。18 关节由参考图人工标定，裙下髋部和遮挡侧关节为估计，带置信度；固定地面线和脚部锚点。伸手草案用相同臂骨长度构建，尚未证明动作或动画质量。它是数据/条件图预设，不是完整蒙皮绑定或关节编辑器。

点“骨骼预设与参考图…”可查看原图、OpenPose 图、叠加校对和正反提示词。单张图识别到站立或伸手动作时自动选择独立姿态条件；未指定动作时沿用角色参考重绘。行走生成使用独立周期骨骼。

基准图片、`rig_v3.json`、姿态 JSON/PNG、提示词及三个 API 工作流保存在 `data/characters/blue_side_v3/`。未修改 AIGAMING 中的 v1/v2 骨架。用户参考图和结果不上传 Git；换电脑需重新安装本地角色基准：

```powershell
& .\.venv\Scripts\python.exe -m tools.install_character_profile '你的角色参考图.png'
```

安装工具使用现有模型，不下载权重，不覆写源图片。不同基准图片不能直接覆写同一角色版本。

切换到另一套 ComfyUI 环境后，可以执行以下命令，把参考图/姿态图重新上传到当前输入目录，导出 UI 工作流并登记到本地工作流库；原 API 文件不变，旧角色配置会备份。该命令会等待引擎空闲，并实际生成一张站立测试图：

```powershell
& .\.venv\Scripts\python.exe -m tools.import_character_workflows
```

导入结果和测试图路径见 `data/controlnet-import-acceptance.json`。连接时校验姿态权重；角色的站立、伸手动作使用当前环境的独立工作流副本。

仓库只保存源码、文档、测试和启动脚本。`.gitignore` 排除了本地环境、生成结果、数据集、模型权重、日志和凭据；克隆后需运行 `setup.bat` 并连接自己的 ComfyUI。`start-comfy.ps1` 中的安装路径应按电脑实际情况调整。

## 启动

1. 已在本机配置独立 `.venv`。首次迁移或重装运行 `setup.bat`（Python 3.13）。
2. 使用已有 ComfyUI Desktop，或者双击 `start-comfy.bat` 启动现有本地 ComfyUI。默认地址 `http://127.0.0.1:8188`。首次启动较慢，日志在 `data/logs`；其他端口在左侧“连接与显存…”更改。
3. 双击 `run.bat`。连接后，在右侧聊天框输入目标提示词，点击“发送并生成”。本机会恢复已安装角色基准；通用创作可在“采样与 LoRA…”里恢复自动工作流。
4. 点击“＋ 参考图”可添加图片，发送时自动上传到本地 ComfyUI 并使用图生图；只有参考图也可以发送。参考图会沿用到后续发送，点击“移除参考图”取消。生成后可点“用这张图继续创作”。
5. 可连续添加任务；当前任务完成后执行下一项。右侧显示预览与消息，可另存 PNG；结果和实际工作流缓存在 `data/jobs`。左侧“生成记录与缓存…”打开记录，双击预览或按需清理；底部“任务与日志”查看队列。

内置 SDXL 文生图/图生图支持尺寸、种子、步数、CFG、采样器、调度器以及一个可选 LoRA。参考图重绘幅度越低越偏向原图，越高越偏向新提示词；加入参考图时按其比例设置尺寸，长边最多 1024，仍可手动修改。模型列表来自服务端真实发现，LoRA 需与 checkpoint 架构匹配；目前没有可测试的 LoRA 或 FLUX 权重。

## 对话输入与后台工作流

左侧“模型与画面…”的后台预设可选自动模式或已移植的工作流。聊天框是正向输入入口，角色模式会附加固定身份描述；反向词在其右侧，应用于下次单张或全部动画帧。采样设置放在“采样与 LoRA…”小窗口，模板使用独立副本，源文件不变。

高级编辑器中点击“用于对话生成”，可将编辑后的工作流设为聊天后台。直接导入 API JSON 也会建立绑定；UI JSON 请在高级编辑器打开。当前自动绑定支持单个 KSampler、可区分的单组正/负提示词（含 ControlNet 转接）；多采样器、多区域提示词等存在歧义时明确报错，不猜测覆盖。自定义工作流的 LoRA 由编辑器配置。

自动模式添加参考图后使用 LoadImage → ImageScale → VAEEncode → KSampler 的真实图生图链路。已绑定工作流若有 IP-Adapter 角色参考输入，会只替换角色参考图，保留独立姿态图；基础 SDXL 空画布工作流可自动加入图生图路径。缺失模型会在聊天中报告，不能因导入成功就认为可运行。

聊天界面按每次输入调用本地模型，未连接 LLM。内置有限中文动作词表与英文条件映射，不能理解所有自然语言或多轮指令；未识别词会提示。继续编辑上一张图片时请用“继续创作”，并填写完整目标描述。普通图生图提供构图和外观参考，不能保证精确语义编辑或角色身份一致。

聊天记录、参考图副本和所选后台模板分别保存在 `data/chat`、`data/references`；任务参数记录实际节点绑定、有效提示词及上传文件名。全部由 `.gitignore` 排除。参考图以随机文件名上传到 ComfyUI 的 `input/AIPictures/references`，不覆盖已有输入。

## 在软件中编辑工作流

点左侧“高级工作流…”可打开嵌入式 ComfyUI 节点编辑器，无需外部浏览器；完成后点“返回创作”。可用节点和权重取决于本机 ComfyUI。

1. 在对话页填好提示词和参数，切换“工作流编辑”，等待编辑器就绪，点击“载入对话配置”。也可用“打开工作流副本…”打开已有 **UI 或 API JSON**。
2. 在画布内修改提示词、模型、尺寸、采样器等，拖动端口连接节点；在画布空白处双击可搜索节点。
3. 日常使用可点“用于对话生成”返回聊天；需直接运行画布的原始配置时点击“运行到软件任务队列”，通过原有队列执行并保存图片。该链路当前面向有 `SaveImage` 输出的图像工作流。聊天发送后，已加载的高级画布会同步本次实际提示词和参考输入；未加载时在下次打开同步。
4. 点击“保存工作流副本…”保存可再次打开的 UI JSON，保留节点位置和连线。执行时任务目录还会额外保存 `editor_workflow.json`，可在工作流页重新打开继续编辑。

编辑器使用 `data/browser` 下的独立浏览器缓存，不读取 ComfyUI Desktop 或外部浏览器的缓存。打开文件在内存中编辑，顶部保存按钮由你选择副本位置。内嵌 ComfyUI 自带的蓝色“运行”按钮仍属于 ComfyUI 自己的队列，其任务不会自动复制到本软件历史；需要统一进度、取消和自动保存时使用顶部紫色按钮。编辑器内 ComfyUI 的保存/设置功能操作的是同一台本地服务。

此功能依赖 PySide6 WebEngine（已包含在锁定依赖中）及运行中的本地 ComfyUI。桥接已针对本机 ComfyUI 0.20.1 / 前端 1.42.15 验证；升级前端后如桥接接口变化，仍需做兼容验证。

### 旧工作流移植

“工作流编辑”页增加了“本地工作流库”，选择条目后点击“打开选中工作流”。列表标明基础依赖是否齐全；连接或刷新模型时重新对照本机节点、模型和输入图片。缺少依赖的工作流仍可打开编辑，补齐之前不应提交生成。

本机 Local Comfy 活动目录的三套侧视角色工作流已复制到 `data/workflows/imported`，索引为 `data/workflows/library.json`；源文件保持不变并记录 SHA-256，相关标准姿态图保存在各副本的 `assets` 子目录。基础工作流已按原参数完成 768×1024、28 步出图；另两套缺少姿态 ControlNet 和部分服务端输入图。姿态图副本可通过 LoadImage 上传；角色参考图需另行选择。

移植记录位于 `data/migration-report.json`，实际加载与出图证据位于 `data/migration-acceptance.json`。用户工作流、素材和生成结果保留本地，由 `.gitignore` 排除。换电脑后可重新导入：

```powershell
& .\.venv\Scripts\python.exe -m tools.migrate_local_workflows --source '你的 ComfyUI 工作流目录' --asset-root '可选的姿态图目录'
```

该工具只复制顶层 UI JSON、复制被引用且能找到的配套图片、登记来源并检查依赖，不下载模型或改写 ComfyUI。源内容相同且本地副本未变时重复导入不会重复创建；源或副本已改动时创建新版本。

旧工作流移植不会覆盖 AIGAMING 与 ComfyUI 源文件，也不安装自定义节点。本次新增的去背景权重仅存于软件自己的 data 目录。

## 测试与验收

在本目录 PowerShell 运行：

```powershell
& .\.venv\Scripts\python.exe -m unittest discover -s tests -p 'test_*.py'
& .\.venv\Scripts\python.exe -m tests.live_smoke
& .\.venv\Scripts\python.exe -m tests.live_editor
& .\.venv\Scripts\python.exe -m tests.live_chat
& .\.venv\Scripts\python.exe -m tests.live_character
```

`live_smoke` 需要运行中的 ComfyUI 和现有 SDXL 权重，会实际执行 768×768、20 步生成，打开真实 Qt 窗口，经窗口的入队逻辑提交，验证下载图片和 QPixmap 预览，保存 `data/acceptance.json` 与 `data/acceptance-desktop.png`。`live_editor` 验证内嵌节点编辑、UI/API 转换和编辑器提交出图，记录在 `data/editor-acceptance.json`。两者都会消耗 GPU 时间并产生图片。

`live_chat` 验证聊天输入覆盖移植模板旧提示词、参考图实际上传与图生图、工作流编辑器输入同步、原文件校验不变；会实际生成两张 768×768、24 步图片，证据为 `data/chat-acceptance.json` 与 `data/chat-desktop.png`。测试使用独立浏览器缓存目录，避免与已打开的软件共用缓存。

`live_character` 用本地角色基准执行真实 SDXL/IP-Adapter 重绘，检查 768×1024 输出、左侧 Inspector、文件弹窗、骨骼预览，以及姿态权重缺失时不提交任务。证据为 `data/character-acceptance.json`、`data/character-studio.png` 和 `data/character-skeleton.png`；需先安装角色基准。

第一阶段验收：连接返回真实 checkpoint；任务进入 ComfyUI 队列；采样进度随事件变化；界面仍可操作；最终图片可预览且 PNG/参数/工作流落盘；重启可浏览结果。取消应只影响本软件当前任务；错误显示在日志并写入 job.json。

手动复查：重复添加两次任务观察串行完成；增加步数后取消当前任务；关闭 ComfyUI 后刷新观察连接错误；另存图片并打开；生成完成后释放显存。程序有后台操作时会阻止立即关闭，避免销毁工作线程，需先取消并等待。

阶段二验收目标：导入已授权数据集→预处理/标注→独立环境完成一轮真实 LoRA 训练→模型版本登记→在第一阶段生成测试图。

阶段三验收目标：编辑保存骨架→关键帧插值→姿态控制真实出图→检查角色一致性和抖动→逐帧修改→导出 PNG/Sprite Sheet/GIF/MP4。

阶段四验收目标：独立视频工作流真实生成→首尾帧与参数可复现→预览导出→验证 12GB 显存策略和取消/错误处理。

模块设计见 `docs/ARCHITECTURE.md`。GitHub 创建步骤见 `docs/GITHUB.md`。
