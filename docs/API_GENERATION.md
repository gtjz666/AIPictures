# 自带 API 的单张创作

实现日期：2026-11-01。默认继续使用本地 ComfyUI；不会在启动时调用收费生图接口。切到云端后，下次启动也不会自动连接本地引擎。

## 推荐使用方式

**中文描述 + 可选参考图 → 支持图片输出的云端模型 → 本地素材处理与保存**。默认只做一次生图请求。先启用云端图片模型本身的理解与编辑能力，复杂需求才打开额外的提示词整理，避免每次多一次请求、增加延迟或改写偏差。

1. 更新已有环境：运行 `setup.bat` 或 `.venv\Scripts\python -m pip install -r requirements.txt`，之后 `run.bat` 启动。
2. 左侧点 **API 与智能生图…**，选择 **云端图片 API 生图**。
3. 在“云端生图”页选择协议/地址预设；填购买服务的 API 基础地址、自己的 Key、准确的图片模型 ID。不要填网页首页或完整 `/images/generations` 地址。OpenAI 兼容平台通常要求基础地址带 `/v1`，按该平台文档填写。
4. “读取模型列表 / 检查连接”只执行 GET，不出图。列表可能包含聊天模型，需要主动选择支持图片输出的模型；若列表接口不开放，可以手动填 ID。不会自动挑模型或切换服务。
5. OpenAI Images 类平台需要明确勾选“支持参考图编辑”才会调用 `/images/edits`；Gemini 原生参考图通过 `generateContent` 的图片部分传入。是否支持编辑、尺寸或画质由平台和具体模型决定。
6. 点 **保存并使用**。主界面仍选择单张图片，描述人物、物件、场景、排版、画风、视角或需要改变的部分。参考图可不选；选图后会显示所选图片。
7. 点 **发送并生成**，查看当前阶段与耗时。没有真实采样百分比时显示等待标识，收图并处理成功后才显示 100%。完成后可放大原图、继续创作、另存或在缓存页清理。

例：参考侧视角色，输入“制作参考角色的正面全身图，面向镜头，保留服装、发型和配色，双手自然下垂”；要大改视角，选择“按描述创作”。“原图小幅修改”在云端是一条尽量保留细节的文字要求，并非保证完全相同的像素锁定。物件/背景不强制套用人物或侧视词。

## 两类 API 分开配置

| 用途 | 输入协议 | 作用 | 是否必须 |
|---|---|---|---|
| 云端生图 | OpenAI Images 兼容 / Gemini 原生 | 真正生成和编辑图片 | 云端模式必须 |
| 智能理解 | OpenAI Chat Completions 兼容 | 将需求整理为正向/反向词及简短方案 | 默认关闭，可选 |

只有 DeepSeek 等聊天 Key：可以在“智能理解”页使用该 Key，再选择本地 ComfyUI 出图；如要减少本机推理，需要另外配置有图片权限的服务/模型。不能仅凭任意 Key 推断平台、获得其他模型或共享额度。服务商地址和模型名称由用户主动指定，不写死“最强模型”。

理解模型默认只收到文字和“是否有参考图”的标记；启用“支持视觉输入”后才同时发参考图，必须选择支持该输入格式的模型。结果严格解析为三段文本；无效方案会在生图前停止。只保存简短方案，不记录模型的私有推理内容。整理不会选择 LoRA、执行模型返回的指令、改网络地址或任意操作工作流。

本地智能生图先冻结界面工作流，再将方案绑定到实际正反文本节点，保留用户主动选择的模型、LoRA、seed 等配置；所用图可在高级工作流中查看。云端请求不伪装成 ComfyUI 图，实际请求参数单独记录。本地 LoRA、CFG、seed、采样器和超分节点不参与普通云端 Images / Gemini 请求，界面停用相应控件；云端大小/画质在 API 页配置。反向词作为文字排除约束传入，不声称为这些图片 API 原生的独立负向条件。

## 文件、数据和取消

- Key 在本机密码框输入，可选仅本次会话；记住时使用 Windows 当前用户 DPAPI 加密、绑定用途与服务地址，不回退为明文。更换地址会清空 Key 输入，不把旧服务的密钥带到新服务。普通设置在 `data/api-settings.json`，密文在被忽略的 `data/api-secrets.local.json`。
- 请求会发送描述、反向要求和主动选择的参考图至配置的服务。不要向不信任的平台填 Key。图像字节可能经该服务返回的图片地址下载，但不向图片地址转发 API Key；含密钥的下载地址、认证重定向都会阻止。
- 每次单图任务冻结设置及参考图到独立 `data/jobs/<唯一目录>/`，修改界面不会改变排队任务。没有参考图时不放置任何默认参考文件。
- 云端文件包括 `api-request.json`（提交快照）、`api-outcome.json`（本地结果状态）、`image_000.png`、`result.json`、`job.json`；开启整理增加 `plan.json`。`api-request.json` 的 submitting 是提交时记录，最终以 outcome/job 为准。不会保存 Key、请求认证头或原始 API 大段响应。整个 data 目录不上传 Git。
- 云端不运行 ComfyUI；选择透明主体时先生成完整图片，再用已有本地 CPU 去背景工具处理。完整画面直接保存返回的原生像素，不进行自动抗锯齿、时间混合或强制缩放。
- POST 生图/整理失败均不自动重试。超时不代表远端未生成，取消只停止本地等待和后续阶段，远端可能继续处理/计费。应先查服务商记录；本版同步协议没有可靠的远端任务查询/取消接口，不声称实现退款或自动恢复付费任务。关闭窗口不等待网络线程，已落盘结果保留。
- 原始云端图片先落盘；后续去背景失败仍保留图片。计费与支持地区由用户所选服务规定，客户端不内置通用 Key 或自动替换服务。

## 本轮检查与限制

新增 HTTP 测试服务返回合成 PNG，验证真实网络请求、multipart 参考图、Gemini 图片内容、图像解码、Qt 队列、预览、缓存、取消、错误脱敏、DPAPI 和重复提交保护。运行：

```powershell
.venv\Scripts\python -m pytest -q tests/test_api_backend.py tests/test_api_ui.py
.venv\Scripts\python -m pytest -q
```

这验证了协议和软件流程，**未使用真实付费 Key 验收云端速度/画质**，不能宣称生成准确率或服务兼容性达到 100%。用户在软件填 Key 后，应分别测试纯文字物件/场景、参考图改视角和最小修改，核对实际效果和平台费用记录。

第一版只做单图。现有动画骨骼仍走本地流程；通用图片 API 没有提供同等的完整姿态序列控制，不能静默丢弃骨骼后冒充同一种动画。也未接入异步厂商视频 API、Responses 工具调用、Anthropic 或任意服务私有协议。需要独立适配时保留现有本地素材处理与导出层。
