# 角色蓝图工作台（插件0.2）

在Godot右侧「AlI素材」点击「角色蓝图工作台」，打开原生独立窗口。可先在空白项目搭建，不会创建角色或示例场景；选中导出的角色根节点后「绑定当前选中角色」。修改完成点击「应用到角色」，再保存Godot场景。也可保存为项目内JSON蓝图，打开复用。关闭窗口后再次打开会保留未应用的编辑。

白色端口连接执行流程，绿色端口连接布尔条件。拖动端口连线，右键端口断线，选中模块按Delete删除；可缩放、平移并用小地图导航。节点位置、参数、连线均支持撤销／重做；应用到角色作为一个独立编辑器撤销步骤。保存蓝图不等于应用到角色，应用后仍要保存场景。

## 常用模块

| 模块 | 用途 |
| --- | --- |
| 按键事件 | 点击节点内按钮改物理键；上端口按住，下端口仅按下触发一次 |
| 事件入口 | 角色就绪、受伤、死亡、落地或动画结束时触发 |
| 封装动作 | 移动、奔跑、跳跃、攻击及常见动作槽；连接已有动画 |
| 播放动画 | 选择角色SpriteFrames动画，随后连接音效或逻辑 |
| 播放音效 | 选择项目WAV／OGG／MP3；动画开始、指定帧（从0开始）或间隔重复，音量可调 |
| 条件分支 | 已落地、空中、移动、奔跑等判断；成立／不成立两个出口，可取反 |
| 布尔变量 | 绿色线接条件输入，替代内置判断；项目脚本也可修改变量 |
| 顺序执行 | 同次事件先执行1、再执行2，不等待动画结束 |
| 延迟 | 等待0.01–60秒再继续，不阻塞主线程 |
| 自定义模块 | 用户编写的项目GDScript；完成／备用两个出口，可复用同一脚本 |

新建预设包含双向移动、四向移动和平台跳跃角色；常用功能组合可以插入「攻击＋指定帧音效」「落地才能攻击」「按键延迟攻击」等可编辑组合。移动／奔跑封装既有角色物理，平台跳跃封装落地判断和跳跃速度，平面跳跃仅播放动画。速度、奔跑倍率、重力和跳跃速度在窗口上方配置。

例如：「J按下 → 已落地条件 → 攻击动作 → 攻击动画 → 第2帧音效」。动作模块不会生成新动画；攻击判定、生命值、技能效果等项目玩法由自定义脚本扩展。冲刺／翻滚／施法等附加槽播放动画并发出`action_requested(action)`信号，不自动赋予完整战斗逻辑。

指定帧和间隔重复音效必须直接接动画；普通执行线接音效时选择「动画开始时」，即执行线到达时播放。重复音效随动画结束或切换停止，同一音效节点避免自身重叠。应用蓝图时关闭旧脚步声循环，避免双重播放。顺序节点的两支都在同次执行中运行，要等待请使用延迟或动画结束事件。

## 可编写模块

点击「＋逻辑／自定义 → 自定义脚本模块」，再点击「新建可编写模块」，保存到当前项目。模板含中文接口说明；点击「在Godot中编辑脚本」编写，也可以选择已有模块。编辑器只检查接口，不实例化该用户脚本；游戏运行时，执行线到达才调用`execute`。

```gdscript
extends RefCounted

func execute(context: Dictionary) -> Dictionary:
    var actor: CharacterBody2D = context["actor"]
    context["variables"]["can_attack"] = true
    actor.set_meta("attack_bonus", 10)
    return {"output": 0} # 0完成，1备用
```

`context`提供角色`actor`、本帧秒数`delta`和共享布尔字典`variables`。项目逻辑也可调用角色`set_blueprint_variable("can_attack", false)`。模块需继承RefCounted，提供一个参数的同步`execute`方法并快速返回；等待使用延迟模块。可在脚本内连接自己的场景、计分、装备、特效等逻辑，复用脚本保留模块接口。

## 保存、运行与边界

应用后的配置嵌入角色场景；新导出的角色包自带运行解释器和校验脚本，运行游戏不依赖AlI或编辑器插件。项目音频及自定义脚本仍通过`res://`引用，迁移时一起保留。旧版角色需要重新导出。

首版主要面向2D角色，数据线仅布尔值，没有UE完整的数值运算、网络复制或任意循环。单图最多200模块／400连线，带每帧执行预算及延迟队列上限。循环连线、缺失动画、越界帧和无效资源阻止应用。蓝图编排已有素材，不自动分析提示词，也不提高生成模型本身的动作准确率。

验证使用独立项目与明确占位帧／短音频：Godot4.6真实编辑器窗口、连线／断线／改键、图内与场景撤销重做、JSON和场景重载；三类角色移动、四向、平台跳跃、指定帧音效、重复音效停止、绿色变量分支、落地条件、顺序与连续延迟、自定义脚本和就绪事件均实际运行。普通无蓝图控制回归通过。原生渲染截图核对布局，静态和引擎检查无错误。验证不涉及新的AI生成或完整游戏玩法验收。
