# AIPictures 使用说明

## 开始使用

1. 启动本机的 ComfyUI Desktop，再双击项目中的 `run.bat`。底部出现“已连接”即可使用；连接失败时，点左侧“连接与显存…”检查地址，默认 `http://127.0.0.1:8188`。
2. 左侧是设置入口，点击后出现小窗口。修改立即用于下一次生成，点“完成”关闭；重新打开会保留刚才的值。同一时间只显示一个设置窗口。
3. 正向提示词和反向提示词并排放在右侧。正向写想要的画面或动作，反向写不想出现的内容。反向词目前建议使用英文；应用角色基准后已有一组默认词，可保留并按需增删。

## 生成人物行走动画

1. 点“角色与生成…”→“应用这张角色基准”，使用当前蓝发侧视角色。
2. 生成类型选“人物行走动画帧”，先用 **8 帧、8 FPS**，然后点“完成”。16 帧会增加生成耗时；FPS 是播放速度。
3. 正向输入：`人物原地向右走路，侧视，全身，保持一致`。
4. 反向可保留默认，或者填写：`different character, changed outfit, extra arms, extra legs, extra fingers, watermark, text, blurry`。这里的内容会送入每一帧的实际负向条件，留空则按空负向条件生成。
5. 点“生成行走动画”。底部显示帧进度，“任务与日志”可以查看执行情况；“取消任务”停止当前任务，已完成的帧留在缓存。
6. 完成后，右侧“画面 / 动画播放”看循环；“全部动画帧”比较各帧并点击单独查看；“精灵图”查看排列。滑动进度条可以逐帧定位。
7. 满意后点“导出动画…”，选择保存地址。ZIP 包括透明 PNG 帧、精灵图、透明 GIF 和播放参数。

本轮开发前展示的 GIF 是本软件通过本地 ComfyUI 完成的八帧实测结果，测试记录为 `data/walk-acceptance.json`。目前还可在“生成记录与缓存… → 动画缓存”双击对应八帧记录播放；用户清除该任务缓存后，需重新生成或打开自行保存的文件。

## 生成单张图片

“角色与生成…”中选“单张图片”，填写正反提示词后点“发送并生成”。应用角色基准时，会附加角色身份描述；检测到“站立”“伸手”等动作会选择对应姿态参考。其他参考图可以通过右侧“＋ 参考图”添加。通用创作可在“采样与 LoRA…”中“恢复自动工作流”。

“模型与画面…”调整基础模型、画布和重绘幅度；“采样与 LoRA…”调整步数、种子、采样器及受当前工作流支持的 LoRA。行走模式固定画布和参考条件，不可调的选项会禁用。单张图生成后自动在本地去背景，棋盘格只用于显示透明区域。点“另存为…”选择 PNG 的保存地址。

## 缓存与保存

- 软件默认把生成任务放在本地缓存，不弹出保存地址。缓存会跨重启保留，直到用户清理。
- 在“生成记录与缓存…”中，图片和动画各有“清除选中”“清空此类缓存”；可多选记录。清理按整次生成任务处理，包含本次图片、原图备份、参数和工作流副本。需要保留的结果应先另存或导出。
- 只有主动点“另存为…”或“导出动画…”时才选择长期保存地址。保存位置必须在任务缓存目录之外，之后可从“已保存文件”页打开文件或所在文件夹。
- 清理缓存跳过当前正在执行和排队的任务，不删除已另存文件、角色基准、导入工作流、参考图或模型。软件只能清理自己管理的 `data/jobs`、`data/animations`，不会清理 ComfyUI 独立保存的输出目录。
- 清除正在预览的缓存后，软件会停止播放并清空对应预览，聊天记录中的失效图片引用也会移除。

## 当前 GIF 的生成逻辑

这版采用固定角色的混合流程：

`参考图人工分层 → 8/16 帧周期骨骼 → 按关节预变形 → OpenPose 条件 + ControlNet + IP-Adapter 肢体修复 → 合成透明帧 → GIF / 精灵图`

行走骨骼由接触、承重、经过、前摆阶段构成，左右腿错半周期，手臂反向摆动。它沿用之前 BODY_18 的关节定义和角色标定，新增了行走周期；站立、伸手两个静态预设不会自动组成一个完整行走。为了减少变脸和换装，头身和鞋尽量保留参考像素，AI 主要修复移动肢体。当前只针对蓝发侧视基准校准，仍有接缝、遮挡估计和机械感。

骨骼窗口目前用于查看和校对，还不能拖动关节。后续可做“选帧拖关节 → 更新姿态和参考图 → 只重生成该帧 → 刷新动画”，本次未实现此编辑器。

## 与参考网站的关系

FrameRonin 的[公开人物动作前端](https://github.com/systemchester/FrameRonin/blob/main/frontend/src/components/NanobananaFullChar.tsx)包含人物动作模板按钮和 GIF 样例；[模板地址配置](https://github.com/systemchester/FrameRonin/blob/main/frontend/src/lib/gemPixelUrls.ts)中，横版人物、一图全动作等入口指向 Gemini Gems。可以确认这部分有云端预设生成入口。

这些公开文件未提供其完整提示词、最新服务端生成管线或可直接复用的骨骼数据，不能据此断定网站使用逐帧 OpenPose / ControlNet。当前软件借鉴的是动作分类和帧预览方式，骨骼周期与本地流程由本项目构建。

## 本次界面与缓存验收

```powershell
& .\.venv\Scripts\python.exe -m unittest discover -s tests -p 'test_*.py'
& .\.venv\Scripts\python.exe -m tests.live_settings_cache
& .\.venv\Scripts\python.exe -m tests.live_animation_preview
```

`live_settings_cache` 在独立的测试缓存中验证浅色模式、提示词布局、弹窗复用、单图及行走负向条件绑定、手动另存、选中/全部清理、排队任务跳过和已另存文件保留，不删除用户真实生成记录。结果为 `data/settings-cache-acceptance.json`。动画预览测试复用之前实际生成的八帧，不重复消耗 GPU。
