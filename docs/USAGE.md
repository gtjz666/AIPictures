# AIPictures 使用说明

## 开始使用

1. 启动本机的 ComfyUI Desktop，再双击项目中的 `run.bat`。底部出现“已连接”即可使用；连接失败时，点左侧“连接与显存…”检查地址，默认 `http://127.0.0.1:8188`。
2. 左侧是设置入口，点击后出现小窗口。修改立即用于下一次生成，点“完成”关闭；重新打开会保留刚才的值。同一时间只显示一个设置窗口。
3. 正向提示词和反向提示词并排放在右侧。正向写想要的画面或外观，反向写不想出现的内容。AI 连续动画接收完整中文；单张 SDXL 会映射常用中文标准词，未识别词会提示，也可以使用英文。

正反词已预填中文通用版本。文字模式在正向开头补充角色外观，按需改朝向、动作即可；选择参考图时默认强调同一角色和配色一致，走路动作仍由生成类型决定。反向已包含重复人物、畸形、裁切、分格、缺色等限制；动画默认另加身份变化、抖动、镜头移动和脚底滑动。切换场景只替换未修改的默认内容，不覆盖用户已经编辑或清空的字段。“恢复默认提示词”可按当前场景重置两栏；它不改变 LoRA 选择。已有角色基准及自动恢复工作流也保留当前提示词，主动导入编辑器工作流仍可载入作者的反向词。

启动时画面与参考图留空，不恢复旧角色参考。点“＋ 参考图”后立即显示用户选择的图片；图片保持原样，生成时才上传本地服务。点“移除”后清空参考图预览与绑定。只输入文字不会使用磁盘上的默认角色图；已有角色基准需主动点击应用。

各生成选项、采样参数及 LoRA 控件都有简短的鼠标悬浮说明，部分下拉选项展开后也可悬浮查看区别。

## 引擎断开与恢复

出现“连接被拒绝 / WinError 10061”表示目标端口没有可连接的服务，通常是 ComfyUI 未启动或已退出。点击底部“启动 / 重连”，或“连接与显存… → 启动本地引擎”，软件会启动已有 `D:\Local Comfy\ComfyUI`，等待准备完成后连接。此操作不安装模型、不更改原环境；其他地址或端口请手动启动对应服务后连接。

引擎断开时，生成按钮禁用，尚未执行的队列保留并暂停。恢复连接后继续未开始的任务；已经提交而失败的任务不会自动重跑，避免重复生成。只有进度通道断开、HTTP 服务仍正常时，会继续查询同一个任务记录并取回结果。启动日志在 `data/logs`，再次启动前备份旧日志；若引擎反复退出，应查看该日志，不能仅凭 10061 判断为模型缺失。

项目启动脚本使用 ComfyUI 的 RAM 压力缓存：可用内存低于 4GB 时允许回收中间节点缓存，不改变采样参数或模型精度。它不能保证 14B 在所有内存负载下稳定；已有运行中的引擎不会被按钮强行重启。

## 尽量保持参考图细节

添加参考图后默认使用“模型与画面… → 参考图策略 → 优先保留细节”。

- 单张图片：参考图进入图像潜空间，重绘幅度最高 0.25；外观以图片为准，文字仅补充支持的动作。较低重绘意味着大幅改姿势的能力也较弱。
- AI 连续动画：直接使用原参考图，不先重绘角色；保留原朝向、视角、颜色、纹样、配饰和鞋面等条件，走路由动画类型决定，文字可补充步速，外观描述不再覆盖图片。
- 该策略下暂停风格 LoRA 和生成式高清修复；原手动选择仍保留，实际生成不使用它们。透明 PNG 的原颜色和 Alpha 在输入准备时保留，之后仅作必要的画布缩放。若自定义预设自带独立姿态控制、作者 LoRA 或高清重画，会提示恢复自动工作流或切到允许重绘，避免默默篡改作者工作流。
- 想改变发色、服饰、画风或大幅调整姿态，主动切换“允许按描述重绘”，再设置重绘幅度、LoRA 和画质。

这些是保真优先的工作流约束，不能保证逐像素一致。静态扩散仍会重绘，连续动画需要推测新姿态与遮挡区域；576×768 的原始动画推理也限制了微小细节。若必须完全保留每个像素，应保留原图，或后续使用可人工校正的绑定动画；本轮未实现该编辑器。

## 手动选择 LoRA 风格

1. 打开“采样与 LoRA…”，在“风格类型”中选择动漫、写实、卡通、插画或像素。
2. 再在“风格 LoRA”中选择具体模型。只选类型时仍是“不使用 LoRA”，不会自动加载第一项；更改提示词不改变选择。
3. 查看下方的适用模型、推荐强度和触发词，按需调整强度。主动选择模型后，会写入对应触发词 / 风格短语；不调用语言模型分析或推荐 LoRA。
4. 单张图片使用该 LoRA；文字动画只在第一张角色图使用，之后由 Wan 延续外观。参考图 Wan 动画及旧版骨骼方式不使用此 SDXL 风格选择，控件会禁用并说明。

当前 10 款模型均为 SDXL 风格模型，[完整列表与来源](LORA_MODELS.md)。自定义单基础模型模板也支持选择 LoRA；模板中原有 LoRA 会保留并叠加，可在高级编辑器调整。其他本地 LoRA 以“未分类”显示，需自行核对基础模型。风格 LoRA 不等同于人物身份模型，不保证肢体、数量、构图或所有提示词都准确。

要改变参考动画的画风，可先选“单张图片”，导入参考，选择“允许按描述重绘”后手选 LoRA，生成后检查结果，再点“继续创作”把结果作为走路动画参考。Wan 延续确认后的画风，避免把 SDXL LoRA 混接到视频模型。

## 图片锯齿与高清修复

- 原图窗口默认启用“平滑缩放”，放大与缩小时都使用平滑变换；查看像素画可关闭。高分屏预览按实际像素缩放，原始文件不因预览变化而改写。
- 标准生成会在透明轮廓的一像素邻域平滑 Alpha，内部 RGB 与不透明区域保留；导入 PNG 的原有 Alpha 不重算，像素 LoRA 不加轮廓平滑。
- “模型与画面… → 画质优化”可手动选择“动漫高清修复”或“写实高清修复”。它们调用本地超分模型再回到所选画布尺寸，会增加耗时；默认“标准平滑”不运行超分。动画只处理选出的 8 / 16 帧，沿用主任务的进度、取消和缓存逻辑。
- PNG / 精灵图保留半透明边缘。GIF 只支持二值透明，仍可能看到阶梯边缘；游戏资源优先使用 PNG 序列 / 精灵图。高清修复改善线条，不能修复已经生成的多余肢体或错误构图。

## 查看图片与输出面板

- 消息记录、任务队列和运行日志合并在底部“输出面板”，默认隐藏。点击右下角“输出面板”或按 **Ctrl+J** 展开 / 收起；面板右上角的关闭按钮也可收起。新消息不会自动展开面板，当前进度仍在底部显示。
- 点击上方静态图片可打开独立预览窗口，读取原始图片。滚轮或“＋ / －”缩放，拖动查看细节；“100%”查看原尺寸，“适应窗口”显示完整画布，Esc 关闭。透明背景继续显示为棋盘格。
- 精灵图也是静态图片，点击可以放大。动画播放区保持播放、暂停和逐帧查看操作，点击动画画面不会弹出放大窗口。
- 验收时可先展开 / 收起输出面板，再点击单图，检查完整显示、缩放和拖动；切到动画播放或暂停后点击画面，应不弹出图片窗口。

## 生成人物行走动画

1. 点“角色与生成…”，生成类型选“动画序列帧”，动画类型选“走路”，生成方式使用 **AI 连续动画 · Wan2.2 14B**。
2. 角色来源选“参考图”，然后点右侧“＋ 参考图”导入人物或卡通角色；也可应用已有角色基准。若选“仅文字描述”，软件先生成一张角色图，再把该图送入动画工作流，不沿用之前的参考图。
3. 先用 **8 帧、8 FPS、20 步**。动画动作由选择框决定，提示词无需包含“动画”或“走路”。有参考图时，可输入 `参考图中的同一角色，自然站立，侧视，全身，保持一致`，也可留空；文字模式需要描述外观，例如 `黄色卡通小恐龙，白色肚皮，大眼睛，全身，侧视`。
4. 反向可填写 `多余手臂，多余腿部，重复人物，颜色缺失，模糊，重影，文字，水印，复杂背景`。Wan 收到完整中文原文；负向条件用于引导生成，不能保证消除所有畸形。单张 SDXL 及旧版骨骼流程另有有限中文词表映射，未映射词会提示。
5. 点“生成行走动画”。底部依次显示参考图准备、整段推理和透明帧处理进度，“输出面板”查看消息和任务。“取消任务”只取消本软件当前任务，已经生成的原始结果留在缓存；CPU 抠图会在当前帧处理结束后响应取消。14B 首次加载、显存卸载均可能耗时较长。
6. 完成后，右侧“画面 / 动画播放”看循环；“全部动画帧”比较各帧并点击单独查看；“精灵图”查看排列。滑动进度条可以逐帧定位。
7. 满意后点“导出动画…”，选择保存地址。ZIP 包括透明 PNG 帧、精灵图、透明 GIF 和播放参数。

旧版骨骼 GIF 的记录为 `data/walk-acceptance.json`；新连续动画的验收分别记录在 `data/temporal-reference-acceptance.json`、`data/temporal-text-acceptance.json`，只在真实运行成功后写入。在“生成记录与缓存… → 动画缓存”双击对应记录播放；清除缓存前先导出需要保留的结果。

连续动画使用 14B 的高噪声 / 低噪声两模型，原始画幅为 576×768，再统一适配到 768×1024 的透明序列画布。8 / 16 帧是最终导出数量，整段推理生成更多连续帧后选择循环区间。调整 FPS 改变导出播放速度；细节一致性和首尾衔接仍需预览检查。

优先保留细节时，连续动画固定沿用参考图朝向；允许重绘或纯文字时，明确写“向左 / 向右”会送入动作描述。纯文字建议把颜色紧邻对应部位，例如“黄色卡通小恐龙，白色肚皮”，避免把颜色与服装混在一起。本机 20 步连续推理曾约 10–12 分钟，内存压力下可能更久；另需处理透明帧，期间界面可继续操作。

本机已启用 BiRefNet general 改善浅色衣物误删。更换抠图模型后，重启软件再生成；已有连续动画可复用原始帧重做透明背景（关闭相关任务后运行）：

```powershell
& .\.venv\Scripts\python.exe -m tools.rebuild_animation_mattes '本项目 data\animations 中的单个任务完整路径'
```

工具先完成全部新透明帧和导出，再替换缓存；旧版本备份在该任务的 matting-backup 子目录。原始视频帧与工作流保留。此功能只重做透明输出，不修复 AI 已经生成的肢体形状。

当前人物和黄色卡通参考图已完成实际行走验证。纯文字模式的角色图仍由 SDXL 生成，测试中还有脚趾变化、白色描边和地面阴影，完整精灵成品质量尚未通过。可先用单张模式检查角色，再“继续创作”作为动画参考；BiRefNet 能改善误删浅色部位，但不能修正原图已经画出的多余内容。高负载时透明处理也可能很慢，本次 8 帧重做约 10 分钟。

## 导入类似的侧视人物

**AI 连续动画**只需要清晰的参考主体，不依赖 OpenPose 的人体关节数量，可用于人物、拟人动物和卡通角色。图片会在本地分离背景、保留颜色并完整放入画布，不把卡通翅膀、短腿强行绑定到人体骨骼。遮挡严重、多个主体或复杂背景仍可能影响生成与去背景效果。

以下人体检测限制只适用于“旧版人体骨骼序列”和人体姿态辅助。单图参考若不适用人体姿态，会退回按参考图重绘，并在消息中说明，不因缺少人体关节而直接阻止出图。

点击“＋ 参考图”选择 PNG / JPG 等图片，行走模式不再限制必须与原蓝发图完全相同。当前适配器优先支持**单人、全身、站立、手臂自然下垂的侧视插画**，保留 PNG 自带透明通道，其他图片先在本地分离主体；按主体比例归一到 768×1024，避免直接拉伸整张画布。

第一次使用一张图时，通过本地 ComfyUI 的 DWPose 识别身体与手部，再适配骨长、手部轮廓、衣摆及地面线。分析结果按图片校验值缓存，整组帧共享同一份识别结果。低置信度、不完整人体和明显不适合的姿态会报告原因，不会静默套用蓝发角色的固定坐标。单张模式输入“站立 / 伸手 / 走路”等已支持动作时，也能使用适配后的姿态与参考图。

可通过以下命令将另一张参考图安装为默认基准（需启动 ComfyUI）：

```powershell
& .\.venv\Scripts\python.exe -m tools.install_character_profile '你的全身侧视图.png' --title '我的侧视角色'
```

每张图使用独立版本目录；紫发新基准和原蓝发基准不会互相覆盖。姿态识别依赖 `DWPreprocessor`；首次使用时由已有预处理插件准备其识别权重。该版本不保证长裙遮住整条腿、复杂道具、长发大面积遮挡、多人物、正面或运动中参考图的自动分层质量，遮挡侧仍由可见侧估计。

## 生成单张图片

“角色与生成…”中选“单张图片”，填写正反提示词后点“发送并生成”。应用角色基准时，会附加角色身份描述；检测到“站立”“伸手”等动作会选择对应姿态参考。其他参考图可以通过右侧“＋ 参考图”添加。通用创作可在“采样与 LoRA…”中“恢复自动工作流”。

“模型与画面…”调整基础模型、画布和重绘幅度；“采样与 LoRA…”调整步数、种子、采样器及受当前工作流支持的 LoRA。行走模式固定画布和参考条件，不可调的选项会禁用。单张图生成后自动在本地去背景，棋盘格只用于显示透明区域。点“另存为…”选择 PNG 的保存地址。

点击参考图旁的“移除”会清除当前参考绑定，恢复仅文字创作，不再暗中使用之前的角色基准。常用中文颜色、卡通动物及标准反向词会映射到 SDXL 条件；这只是有限词表，单图当前仍使用原 SDXL 模型，不等同于完整中文语言模型。

## 缓存与保存

- 软件默认把生成任务放在本地缓存，不弹出保存地址。缓存会跨重启保留，直到用户清理。
- 在“生成记录与缓存…”中，图片和动画各有“清除选中”“清空此类缓存”；可多选记录。清理按整次生成任务处理，包含本次图片、原图备份、参数和工作流副本。需要保留的结果应先另存或导出。
- 只有主动点“另存为…”或“导出动画…”时才选择长期保存地址。保存位置必须在任务缓存目录之外，之后可从“已保存文件”页打开文件或所在文件夹。
- 清理缓存跳过当前正在执行和排队的任务，不删除已另存文件、角色基准、导入工作流、参考图或模型。软件只能清理自己管理的 `data/jobs`、`data/animations`，不会清理 ComfyUI 独立保存的输出目录。
- 清除正在预览的缓存后，软件会停止播放并清空对应预览，聊天记录中的失效图片引用也会移除。

## 当前 GIF 的生成逻辑

默认 AI 连续动画：

`参考图 / 文字生成角色图 → 整段 Wan2.2 14B 连续推理 → 本地主体分割 → 统一尺度、地面与位置 → 选择较接近的首尾区间 → 透明 PNG / 精灵图 / GIF`

该流程不使用人体关节识别，不复制或切开参考图的肢体。两段采样共享视频潜空间；高噪声和低噪声模型衔接，中文正反向描述直接进入 Wan 的文本条件。先用原始帧的小缩略图选择循环区间，只对最终 8 / 16 帧进行分割，每 4 帧释放并重建 CPU 模型会话以限制缓存占用。整帧稳定处理只作统一缩放和平移，保持同一尺度，不单独拉伸四肢。模型生成依然可能出现动作或外观瑕疵，自动循环区间选择不保证首尾完全无缝。

保留的旧版人体骨骼混合流程：

`参考图主体与手部识别 → 按人物适配 8/16 帧周期骨骼 → 连续肢体网格预变形 → OpenPose 条件 + ControlNet + IP-Adapter 关节细节修复 → 合成透明帧 → GIF / 精灵图`

行走骨骼由接触、承重、经过、前摆阶段构成，左右腿错半周期，手臂反向摆动。沿用 BODY_18 的关节定义，关节坐标与骨长来自本次参考图；站立、伸手两个静态预设不会自动组成完整行走。网格连续覆盖手肘、膝盖，手挡住的腿部从同图可见颜色补齐，不再使用写死的白衬衫、蓝裙颜色。

颜色处理改为 straight RGBA：去背景只计算 Alpha，不再次把 RGB 乘以透明度；已透明的图片避免重复分割。AI 仅修复局部关节，RGB 单通道变化限制在 16 级以内，Alpha 来自共享网格；每帧 `quality.json` 记录颜色改变量与不透明主体像素数。GIF 共用前景调色板，透明索引独立，避免黑色衣物被误用作透明色。PNG 保持完整色彩，GIF 仍受 256 色格式限制。自动遮挡补全仍可能留下衣摆、手部和绑定接缝。

骨骼窗口目前用于查看和校对，还不能拖动关节。旧版骨骼后续可做“选帧拖关节 → 更新姿态条件图和节点输入 → 只重生成该帧 → 刷新动画”。默认 Wan 连续流程目前没有姿态控制输入，不能直接靠拖动 BODY_18 节点精确控制；要加手动骨骼需另接经过验证的姿态序列条件模型，按连续片段重生成并检查帧间一致性。本次未实现此编辑器。

## 与参考网站的关系

FrameRonin 的[公开人物动作前端](https://github.com/systemchester/FrameRonin/blob/main/frontend/src/components/NanobananaFullChar.tsx)包含人物动作模板按钮和 GIF 样例；[模板地址配置](https://github.com/systemchester/FrameRonin/blob/main/frontend/src/lib/gemPixelUrls.ts)中，横版人物、一图全动作等入口指向 Gemini Gems。可以确认这部分有云端预设生成入口。

这些公开文件未提供其完整提示词、最新服务端生成管线或可直接复用的骨骼数据，不能据此断定网站使用逐帧 OpenPose / ControlNet。当前软件借鉴的是动作分类和帧预览方式，骨骼周期与本地流程由本项目构建。

`live_settings_cache` 在独立的测试缓存中验证浅色模式、提示词布局、弹窗复用、单图及行走负向条件绑定、手动另存、选中/全部清理、排队任务跳过和已另存文件保留，不删除用户真实生成记录。结果为 `data/settings-cache-acceptance.json`。动画预览测试复用之前实际生成的八帧，不重复消耗 GPU。

`live_preview_controls` 复用 `data/walk-acceptance.json` 中已生成的序列，验证输出面板默认隐藏、按钮 / Ctrl+J 切换、静态原图放大、滚轮缩放、100%、适应窗口、Esc 关闭，以及动画播放 / 暂停 / 逐帧点击不放大。无需连接 ComfyUI，也不修改用户历史；结果为 `data/preview-controls-acceptance.json`。

`live_walk` 使用当前默认角色实际生成八帧，核对八个真实任务、每帧颜色上限、透明输出、预览与导出；`live_reference_import` 通过真实界面导入另一张图，验证其校验值进入识别、姿态和参考绑定，并实际生成一张透明图片。导入验收记录为 `data/reference-import-acceptance.json`；以上两项需要 GPU 时间。

`live_walk` 显式测试旧版骨骼后端；`live_temporal_walk` 执行真正的 Wan2.2 14B 连续推理，分别验证卡通参考、无需动画关键词、中文负向条件、文字生成角色、透明八帧和播放器。需要安装已批准的 14B 模型，且耗时明显高于结构测试。`live_nonhuman_image` 验证人体姿态不适用时仍能通过真实参考重绘生成单图。
