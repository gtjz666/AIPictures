# AIPictures 使用说明

## 启动与界面

1. 如需同时打开 Comfy Desktop，先启动它，再双击 `run.bat`。软件启动或重连时优先使用 Desktop 的实际本地端口；“连接与显存…”与高级工作流显示同一地址。没有现有服务时，“启动 / 重连”才启动独立 8188。自定义端口保持显式设置。正在执行/排队的任务不迁往另一服务。
2. 左侧设置按钮打开小窗口，修改用于下一次任务。参考图启动留空，点“＋ 参考图”立即显示所选图片；“移除”清除绑定。
3. 右侧正反提示词启动留空，不自动添加默认模板；切换模式保留用户文字。[不同视角、物件、背景和动画测试词](GENERAL_TEST_PROMPTS.md)可手动复制。参考强度和 CFG 在提示词旁调整。
4. 当前任务名称、百分比、细进度条及持续更新的已用时集中在左下角，隐藏内部任务序号。消息、队列、日志在默认隐藏的“输出面板”，按钮或 **Ctrl+J** 切换。

点击静态图片或精灵图可放大，支持滚轮、拖动、100%、适应窗口和 Esc。动画播放区域保持播放和逐帧操作，不弹出图片放大窗口。棋盘格仅用于预览，不会写进图片。

## 生成动作动画

1. 打开“角色与生成…”，生成类型选 **动画序列帧**。
2. 动画类型选 **走路 / 待机 / 跑步 / 跳跃 / 伸手**。默认 **自动适配完整骨骼**，无需手动操作；动作选择优先，提示词无需出现“动画”或“左右交替”。
3. 角色来源选“参考图”，导入单个全身双足人物；或选“仅文字描述”，填写角色外观。文字模式先生成静态角色图，不沿用旧参考文件。
4. 首次使用建议 **8 帧、8 FPS、20 步**。有参考图时正向可以留空；反向按需填写。所选动作的提示与姿态会在后台自动加入实际条件，不依赖提示词是否提到动画。
5. 点“生成对应动作动画”。左下角显示任务名称与百分比，输出面板查看具体阶段。完成后右侧循环播放，可查看全部帧和精灵图。
6. 满意后点“导出动画…”，选择保存地址。ZIP 包含透明 PNG、精灵图、GIF 和动作/FPS 等播放参数。删除缓存前先导出。

需要真正的像素素材时，使用旁边的 **导出像素素材…**，选择网格、画布、调色板及锚点，导出 PNG、Sprite Sheet、metadata、配置和报告。此路线不做全局抗锯齿、超分或时间混合，默认不缩放内容；预览为最近邻。新生成动画优先使用原生透明帧。详见 [像素精灵管线](SPRITE_PIPELINE.md)。

每个动作均生成完整姿态序列：8 帧输出对应 17 张实际模型输入，16 帧对应 33 张；左右半周期完整保留，重复终点不导出。FPS 仅改变播放速度。跳跃导出保留离地高度，不会把每张图重新压到地面。

当前默认为 **Wan Animate 14B**，不是之前只输入参考图的自由 I2V。实际条件是参考图、中文正反词和所有姿态帧；原生画幅 480×640，透明输出为 768×1024。12GB 显存依赖卸载，首次模型加载较慢；本机 8 帧常规测试约 641 秒，不能作为固定速度承诺。

有参考图时保留“优先保留细节”，动画导出会自动按原图校正前景配色，无需新增提示词。全部帧中的“待复查”表示仍有不确定局部颜色，需要点开检查；校色不能恢复已经变形的花纹、手指或鞋型。旧动画不会自动改写，本机新增的“配色修订”缓存可直接查看或重新导出。完整方法及无需重新推理的修订命令见 [动画配色说明](ANIMATION_COLOR_WORKFLOW.md)。

## 可选的骨骼调整

帧卡、画布和标题显示当前帧数与动作阶段；可用滑条或方向键逐帧定位。点击“播放完整动画”预览修改后的完整周期，支持循环和慢放。人物示意按参考取色，用于动作校对；不是 AI 成品。详情见 [动作与颜色说明](MOTION_REFINEMENT.md)。

添加参考图后点击左侧 **动作骨骼…**（或角色设置内对应按钮）。自动识别本次图片并生成所选动作完整周期。

- 选择“基准骨架”调整角色比例，会重新生成全周期；选择动作帧后拖关节，只改变该关键帧。
- 脚踝、脚跟、脚尖分别调整，每条腿只有一组足部控制；可预览整套骨骼、重置当前帧或恢复自动周期。
- 点“保存并用于生成”后切到手动方式。数据按参考图与动作独立保存；改换图片、动作或帧数后应重新打开校准。
- 只想直接生成时选回“自动适配完整骨骼”，不需要手调。手动修改的是实际 pose_video 输入；之后重新生成整个片段，不是只替换一张帧图。

检测不到人体时会按本次主体轮廓估计双足布局并提示。短腿拟人动物可进入流程，但遮挡侧和步幅可能不准；四足、无足及机械结构尚无专用布局。不能把“流程能运行”等同于“动作完全准确”。编辑标准坐标面朝右，左向参考在导出时恢复方向。

单一静态骨骼在两组实际测试中未能形成完整走路周期，因此没有保留在常规选择栏。自动完整骨骼提供同样简单的操作，不依赖用户补充动作关键词。

## 参考图细节与足部检查

“模型与画面… → 参考图策略”在单图默认 **按描述创作**，允许改视角/姿势；需要少量修改时选“原图小幅修改”，潜空间重绘最高 0.25，暂停风格 LoRA 和高清重画。动画单独保存参考保真策略，直接使用参考，不先改画风。

动画仍会重新推测遮挡与运动形状，不能逐像素锁定参考。每次任务保存 `foot-review.jpg` 及逐帧 `feet.png`，便于检查鞋底、脚尖和脚踝。浅色鞋参考若出现原图没有的小范围蓝色漏色，会做局部中性色修正，保留修正前图和 `foot-quality.json`；原图蓝鞋或深色鞋跳过。它只修颜色，不证明脚掌数量、鞋型或细节完全正确。

目前走路有常规 20 步端到端测试；新增四种动作有快速推理预览。细小手部、鞋面、遮挡、首尾接缝和不同体型仍需人工检查。卡通短腿步态已有反例，不宣称接近 100% 成功率。

## 单张图片与手动 LoRA

“角色与生成…”选“单张图片”，可以描述人物、物件或完整场景。默认保留背景；需要独立游戏资产时主动选透明主体。添加参考图提供外观条件；参考强度越高越接近参考，过高可能抑制改视角，0 表示不使用参考。CFG 不是百分比，过高可能过曝。自定义工作流的独立参考节点不猜测绑定权重。

“采样与 LoRA…”先选风格类型，再主动选具体模型。只选类型不加载模型，提示词不会分析或切换 LoRA。显示兼容模型、强度和触发词；12 款 SDXL 风格见 [LoRA 说明](LORA_MODELS.md)。它们作用于单图及文字动画前置角色图，不混接 Animate。内部快速测试的加速权重不出现在风格栏中。

动画按官方 CFG 1 运行，常见反向排除项同时整理成正向生成要求，原反向文本仍保留；不等同于高 CFG 的负向分支采样。动画使用 Wan 文本编码器接收完整中文；单张 SDXL 仍用有限中文词表，未覆盖内容会提示，不等同于通用中文语言理解。负向提示词是条件引导，不保证消除所有错误。

预览默认平滑缩放，可在原图窗口关闭以查看像素画。单图可手选本地动漫/写实高清修复；完整动作当前不套用生成式超分。PNG 保留半透明轮廓，GIF 二值透明仍可能出现阶梯边缘；游戏素材优先 PNG。

## 保存与缓存

默认输出为缓存，不弹出保存地址。“另存为…”或“导出动画…”才选择长期保存位置，必须在缓存目录外。

“生成记录与缓存…”可双击打开旧图/动画，清除选中或全部缓存；跳过运行和排队任务，保留外部已保存文件、模型、参考图、角色基准和工作流。ComfyUI 自己的输出目录不在清理范围内。

新动作缓存包含 `motion.json`、`poses/`、`video/workflow.json`、原始模型帧、透明帧、姿态和足部检查、GIF 与精灵图。原始图保留供排查，模型和缓存均不上传 Git。旧动画仍可打开；现有 `rebuild_animation_mattes` 命令仅针对历史自由 I2V 缓存，不用于新 Animate 缓存。

## 引擎恢复与工作流

WinError 10061 表示目标端口没有可连接的服务，先“启动 / 重连”。启动复用现有环境，日志在 `data/logs`，不覆盖 ComfyUI；已有服务不会强制重启。断线后暂停未开始的任务；已提交失败任务不自动重跑，进度通道单独断开时继续查询同一个任务结果。

“高级工作流…”可打开本地 ComfyUI 节点编辑、保存副本和运行到软件队列；原文件保留。自动对话绑定目前面向单采样器图像模板，复杂多区域/多模型图仍需在编辑器配置。节点存在不代表权重齐全，安装说明见 [动作模型](MOTION_MODELS.md)。移植步骤见 [README](../README.md)。

## 复测与后续

在项目目录运行：

```powershell
& .\.venv\Scripts\python.exe -m unittest discover -s tests -p 'test_*.py'
& .\.venv\Scripts\python.exe -m tests.live_motion_editor
& .\.venv\Scripts\python.exe -m tests.live_preview_controls
& .\.venv\Scripts\python.exe -m tests.live_settings_cache
& .\.venv\Scripts\python.exe -m tests.live_pose_motion --reference '你的全身参考图.png' --action walk
& .\.venv\Scripts\python.exe -m tests.live_pose_studio
```

最后两项真实调用 14B，耗费 GPU 时间；`live_pose_studio` 使用本机固定测试参考，其他电脑应改为自己的测试文件。`--fast --raw` 是快速行为诊断，`--static` 仅用于复现被舍弃路线，不是常规生成入口。快速预览不能替代常规参数的成品验收。

检查标准：界面不阻塞、动作选择进入实际提示和姿态输入、完整周期导出、透明背景、可播放/逐帧/保存、任务名与百分比同处且无序号；视觉另查肢体、鞋子、身份、循环接缝。历史测试与失败记录见 [本机验证](VALIDATION.md)。

面向游戏开发者的下一步是角色、物件、背景三类入口，再做角色项目、统一枢轴/尺度与引擎导出，之后扩展一致性、训练和视频。具体范围见 [路线](GAME_ART_ROADMAP.md)。
