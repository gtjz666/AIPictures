# 动画模式与长任务处理

五种常规动作（走路、跑步、待机、跳跃、伸手）共用 `pose_animation.generate`。界面选择决定完整动作描述和连续骨骼，不需要用户额外写“动画”或“左右交替”。默认都使用 768×1024、20 步、CFG 1、Euler、保留生成原色，以及生成结束后再去背景。没有为其他动作启用旧的单一静态骨骼、自由 I2V、快速 LoRA 或低分辨率回退。

## 真实执行阶段

1. 参考骨架与完整周期：8 张导出帧对应 17 张独立姿态输入，16 张对应 33 张。播放 FPS 不改变模型帧数。
2. 采样任务：只生成和保存潜变量；`video/workflow.json` 是实际提交的图。
3. 解码任务：空闲时释放模型缓存，读取同一潜变量，用原生 VAE 解码；`video/decode/workflow.json` 不包含采样器。
4. 单帧去背景、保留生成 RGB、组装精灵图、导出 GIF。原始 RGB 与潜变量保留。

每个 ComfyUI 阶段新增 `monitor.json`：记录后端地址、任务标识、排队/运行/取消确认/下载状态、正在执行的节点类型、最后采样进度和本阶段累计时间。`sequence.json.timings` 分别记录采样等待与下载、解码等待与下载、去背景与打包耗时。节点间加载模型也计入等待，不能把它描述为纯采样时间。

界面区分“编码参考与连续骨骼（采样前）”“动作采样”“解码原生动画帧”“等待共享引擎”等阶段。窗口持续显示任务耗时。进度连接中断后使用同一任务标识读取历史；只读请求的临时超时会继续检查。已完成图片下载超时，只重试读取该文件，写入临时文件后替换，不重新采样。

常规生成不再以固定的 30 分钟或两小时总时长判失败；连接和单次读取仍有短超时，用户可以取消。后端真实拒绝连接、节点错误和后端连续三次同时没有队列与历史记录仍会明确报错，避免永远空等。显式传入 `ComfyClient.generate(timeout=...)` 仍可用于诊断。

点击取消后，只删除/中断本任务，并等队列确认本任务停止；即使先收到中断事件，也等待清理完成。确认前不推进软件下一任务，也不卸载其他客户端正在使用的模型。后端取消某些编码节点需要等当前计算返回，不能承诺立即停止。

## 动作终点

走路、跑步、待机、伸手按完整周期取帧，排除重复终点并循环。跳跃保留从准备到最终恢复站立的末帧：8 帧取原始 17 帧中的 `0,2,5,7,9,11,14,16`。跳跃的手动关键帧使用包含终点的时间轴，不跨末帧混回首帧。软件预览与导出 GIF 单次播放到末帧，“重播”从首帧开始；骨骼预览也默认不循环跳跃，仍可手动勾选循环。

## 本机检查与复现

2026-10-30 的用户记录中，走路完成约 842 秒；随后跑步在约 1069 秒取消，取消后后端仍一度显示该任务运行。记录没有显示该次由客户端总时长限制抛出 `TimeoutError`。同时发现独立 8188 后端和 Desktop 8189 后端并存、端口与数据库锁冲突。不能仅凭这两点证明所有长等待的唯一原因。确认双方队列空闲后关闭了重复的独立实例，本轮实测统一使用 Desktop 的 8189 后端。

标准参数的实测使用同一参考图与固定 seed，四种动作依次执行；不会并行预处理、去背景或提交四个大模型任务。测试入口需要显式传入存在的参考图，不再引用已经被清除的历史缓存：

```powershell
python -m tools.verify_animation_modes --reference "参考图完整路径.png" --out data/action-check --actions run idle jump reach
python -m pytest -q
python -m tests.live_animation_modes
python -m tests.live_motion_refinement --sequence "已准备好 reference_analysis.json 和 motion.json 的动作目录"
```

`acceptance.json` 检查动作、帧数、尺寸、透明通道范围、原色保留、完整取帧和精灵图逐像素回读。`overview.png` 由真实导出帧组成，采用最近邻预览，不修改实际输出。数值通过只能说明管线正确执行，人物身份、衣物结构、颜色和动作自然度仍需逐帧视觉检查。

若目录已有未完成任务，测试工具会停止并指出原记录，不能再次使用同一输出目录悄悄重跑。`ComfyClient.resume` 可按已知任务标识继续只读检查/下载，不提交 `/prompt`；后端已重启且任务历史消失时，需要先核对已保存潜变量与原图再决定恢复。
