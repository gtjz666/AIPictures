# 面向普通游戏开发者的生成路线与 FrameRonin 调研

调研日期：2026-10-29。本文是方案，不代表 API 已接入，也没有进行付费调用或上传用户素材。

## 建议

现有本地图片、骨骼动画、预览与导出已经有真实执行链路，无需把进一步优化 14B 本地动画作为 API 开发的前置条件。先完成当前连接与导出缺陷修复，再优先接入用户自带密钥的图片 API；本地推理保留为可选执行方式。轻量软件负责项目、素材、骨骼、预览和导出，推理由所选服务负责。

API 解决下载、显存和算力门槛；不会自行修复错误骨骼、重复手指、运动模糊、色彩漂移或抠图问题。游戏动画验收应按帧检查，不能把“视频看起来连贯”当作素材可用。

## FrameRonin：已观察与未确认

实际打开 frameronin.com 首页，当前显示 V5.0，可见“API 设置”“API 生图”“自由序列”“视频转序列帧”“Sprite Sheet 调整”，以及角色、场景、建筑、图标等独立用途入口。自由序列说明为上传角色参考图并描述动作。页面链接的源仓库为 systemchester/FrameRonin。

公开仓库 README / 产品文档仍标 V3，不能将旧文档当作线上 V5 的全部实现。文档明确描述视频探测、抽帧、抠图、画布整理、PNG/ZIP/索引导出，以及按帧偏移和重排。没有从这些信息证实线上采用了哪套逐帧骨骼约束、什么隐藏模型，或达到了某种准确率。没有登录、充值、复制网站代码或提交素材。

最值得借鉴的是把生成与素材加工分开：角色参考确认 → 明确动作 → 生成候选 → 逐帧审查 → 整理透明序列 → 游戏导出。拆分网格与输出排列是不同设置，改变输出列数不应重新切割原图。

## 我们的改进方向

| 用途 | 普通用户操作 | 本地保留的处理 |
| --- | --- | --- |
| 角色动画 | 导入角色，或先按文字生成并确认角色；选动作、方向和时长 | 骨骼编辑/示意预览、逐帧检查、透明输出、序列排布、FPS、导出 |
| 物件 | 选物件、画风、视角、尺寸，输入描述/参考 | Alpha 检查、裁边与边距、尺寸整理、保存 |
| 背景 | 选场景、视角和画幅 | 大图预览与保存；完整场景默认保留背景，透明图层另选 |

界面先按用途组织，再选择“API / 本地”。普通入口提供中文描述和少量必要选项；手动骨骼与节点编辑是可选的精细控制。API 模式不自动启动本地 ComfyUI、不加载本地大型生成模型。

动画先输出一个短动作供确认，再扩展动作集合。每个动作保留同一角色基准、固定画布、取样时间、循环范围和地面基线；跳跃保留根位移。后续增加单帧/相邻短段修复和遮罩修正，避免一个坏帧要求整段付费重跑。修复能力必须由服务实际支持，不能承诺任意视频接口都有。

云端若返回无损 PNG 帧优先采用；从有损视频提帧可能把压缩伪影带入手部与轮廓。去背只操作目标背景，不用色键误删同色衣服。白/黑/棋盘背景及游戏实际显示尺寸均用于检查。像素风采用最近邻与人工调色板控制，插画风采用平滑缩放，二者不能共享一个强制滤镜。

## API 候选与能力边界

| 路线 | 适用 | 已核实限制/成本方式 |
| --- | --- | --- |
| 阿里云百炼官方图片 / Wan 动作 API | 中文用户的第一批接入候选，分别评测图片与动作服务 | 官方提供图片模型接口；Wan 图生动作接收人物图和表演视频，不是逐帧骨骼接口。北京/新加坡的密钥和域名不能混用；先测实际效果与费用 |
| BFL 官方图片 API | 单张角色基准、物件、背景的候选服务 | 按图像/规格计费；图片接口不能据此推定支持骨骼动画或所有本地 LoRA |
| fal Wan Animate Move | 动作视频 + 角色参考图的动画候选 | 官方 schema 接收 video_url / image_url，可请求 frames_zip；没有公开 pose_video 参数，也没有单独用户正负词输入。不能把彩色骨骼视频直接当作可用的人物动作视频 |
| Comfy Cloud / Comfy API 部署 | 希望保留现有完整骨骼图、模型、工作流的远程推理候选 | 官方支持工作流 API、素材上传、任务与结果；Cloud 工作流 API 需要付费订阅，部署另有 GPU 启动/工作/保温时长费用。当前节点/权重可用性仍需实际部署验证 |

本地 ComfyUI、Cloud 工作流 API 和直接图片模型 API 是不同协议。当前 ComfyClient 只允许本机 HTTP，不应简单删除限制并把任意 HTTPS + Key 当作已兼容。远程工作流需要独立适配，使用供应商明确支持的协议。

目前没有付费实测各服务的角色一致性、中文描述效果、跨地区网络可达性、配额或计费失败情况，因此不对“最好模型”或一次成功率排序。具体报价提交前获取，界面显示币种、分辨率、时长和估算依据；不把临时活动价写死。

## 最小接口设计

- GenerationRequest：用途、正负词、参考资产、动作/骨骼资产、画布、时长、帧数、种子、手选风格。
- BackendCapabilities：文生图、图生图、透明输出、负向词、逐帧骨骼、首尾帧、局部修复、LoRA、取消、费用估算、真实进度。界面仅展示当前后端支持的项，不静默丢弃骨骼。
- GenerationBackend：能力查询、估价、素材提交、任务提交、任务查询、取消、结果下载。LocalComfy / RemoteComfy / ImageProvider / VideoProvider 分开适配。
- GenerationResult：提供商、远程任务号、有效参数、原始结果、帧时间、透明处理和修复记录、耗时、质量待复查项。所有后端共享现有本地素材库和导出。

密钥由用户在软件本地输入，存 Windows 凭据管理器或系统保护存储，普通配置只存凭据引用；不写入 Git、工作流 JSON、日志、截图或浏览器节点。软件不内置开发者通用密钥。用户自带密钥模式不需要先建设账户充值平台。

接口提交超时后先用远程任务号查询，不盲目重试导致重复收费；只有服务支持幂等键时才依赖其去重。取消是否停止计费按提供商实际行为提示。没有真实逐步进度时显示排队/生成/下载阶段和已用时间，不伪造精确百分比。

参考图会发送给用户选择的服务，提交界面明确显示服务、输入素材和费用范围；不后台替用户调用其他服务。地域、服务条款和素材使用条件需要随所选服务核验。

## 实施顺序与验收

1. 完成当前共享后端、编辑器与实际图一致、透明边缘修复；保留原始结果。修复代码通过测试不等于重影已彻底消失。
2. 第一个 API 版本只接一家图片服务：文字/参考图 → 真实 API → 下载 → 预览 → 本地保存；密钥不外泄，API 模式不加载本地大模型；没有密钥时明确未配置，不提供假生成。
3. 加物件/背景用途预设，固定中文表单和输出规则；风格仍由用户主动选择。
4. 用同一参考集评测动画服务，包含动漫人体、写实人体、卡通双足；检查整周期、手脚、颜色、Alpha、循环与耗时。支持骨骼条件的远程 Comfy 工作流与普通动作视频接口分开评测。
5. 再实现短段修复、导入游戏需要的索引、pivot/事件标记等；分层绑定与非双足布局另作功能验证。
