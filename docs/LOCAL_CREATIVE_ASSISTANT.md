# AlI 工作台与本地识别

软件按“选择图片/动画 → 添加素材和描述 → 生成 → 预览、选择保存”操作。
默认固定为左右两部分：左侧是成品棋盘、播放/导出和底部任务；右侧顶部「单张图片 / 动画」两个标签切换，同一时间只显示一个工具页；提示词在「查看／编辑提示词」弹窗中查看和修改。记录、画面、采样、连接、API、窗口位于顶部。

## 日常操作

1. 顶部选择「单张图片」或「动画」。将文件拖入棋盘画布；下方不再有单独聊天拖入框。图片/视频/GIF/PNG动作帧会分配到对应区域，多PNG会确认用途并询问FPS。
2. 导入只复制、解码和预览，不启动识别。「单张图片」页上半显示1–4张参考图、下半填写参考要求；参考动画与独立播放器移到「动画」页顶部，可暂停、定位。也可以直接往参考区拖入文件。悬停右上角×移除对应素材。左侧不显示参考内容，查看、导入、播放或移除参考都不覆盖成品。
3. 在参考要求里用中文描述目标，点「生成提示词」；中文正反提示词在「查看／编辑提示词」弹窗中显示并可直接修改，提交图片引擎时使用同一次整理产出的英文，界面始终保留中文。动画内容分析与「分析动作」按钮已取消；替换素材不会调用识别，也不会删除手填的成片动作要求。没有安装本地助手时会直接提交界面上的中文，不静默改写。
4. 提示词弹窗中「正向提示词」标题右侧选择「人物／外观」「风格」「自定义」。人物侧重身份与衣物配色；风格只传画法，不把参考人物身份、服装或站姿当成目标；自定义展开说明框，填写要保留/改变的部分，本地模型按该用途观察再整理正反词。用途选择由用户决定，更改不会自动识别；空自定义说明会提示补充。当前一次使用一张静态图和一份动作素材，动作素材仍只提供动作、镜头与节奏。
5. 「动画」页的循环、起点滑条和时长调整实际参考区间。下方始终提供空白自定义动作表，填写开始秒、结束秒和动作后同步提示词；可以添加/删除时段，空表直接跟随参考。时间为成片时间，不自动按新时长拉伸；不完整或越界时段需要修正后再生成。PNG仍支持顺序/FPS和起点预览，不再显示内容识别页。
6. 画布下方保留播放/导出。完整动画先循环预览，再自主勾选源帧导出。任务位于左侧底部，不横跨右侧，只显示名称、进度和耗时；失败时点击任务名查看原因。实际种子到顶部「采样」中复制/复用。
7. 区域位置固定。左右分隔线调整画布与工具区宽度，弹窗中正反提示词之间的分隔线调整各自高度；工具页空间不足时可滚动。尺寸关闭时保存，启动固定打开「单张图片」页；「窗口 → 恢复默认布局」还原，旧自由停靠状态不再恢复。右侧标签只切换视图，输出类型仍由顶部选择。导入和点击生成不会附带调用本地识别。

存在歧义、素材发生变化、输出不完整或模型失败时，保留原输入并停止在识别阶段，不继续提交生成。
识别和生成在本软件中串行运行。当前队列繁忙时先等待完成；助手不会重启共享ComfyUI或取消其他客户端的任务。

## 模型与隔离

- 官方 `Qwen/Qwen3-VL-8B-Instruct-GGUF`，语言部分Q4_K_M，视觉投影F16；两者必须配套。原Z/FLUX/H3编码器不替换。
- 动作分析原本共用这套模型，没有可单独删除的动作识别权重。停用动作分析后保留它，继续用于参考图用途/外观识别与正反提示词整理；不因删除共用模型破坏这些流程。
- 中文提示词整理完成后，复用同一个已加载会话再做一次纯文本英译，得到界面对应的英文提交词；不重新发送参考图，也不额外启动第二个识别进程。只有用户手动修改中文时才再跑一次纯文本转换。英文转换失败会保留中文并写出 `english-error.json`，不会悄悄提交旧英文。
- 独立、固定版本的Windows llama.cpp CUDA12.4运行包，不向桌面Python或ComfyUI安装Torch/修改依赖。
- 安装到独立目录，模型不进Git。按官方发布SHA验证；可用Qwen在ModelScope的镜像传输同一文件，仍须匹配原发布SHA。
- 服务仅绑定127.0.0.1的临时端口，不使用云端Key。分析完成/取消/失败后，自己的进程退出并释放显存，之后才允许生成。
- 固定识别采样seed42用于可复现方案；它与图片/动画的生成种子独立，不会修改用户的随机/固定种子设置。
- 读视频/GIF/PNG帧并保留时间信息，最多12张、动作缩略图448像素长边；静态图672像素长边。原始文件与原RGB保留。这是理解用的证据，不替代生成参考。
- 分别观察外观和动作，再用结构化事实整理中文提示词，避免立绘站姿覆盖动作取景。人物动作中出现“前爪”等源动物结构时，增加一次有限文本校对；校对未通过就不提交生成。它不是完整的解剖准确性判定器。
- 参考用途决定读图任务和计划上下文，`reference_usage`随识别记录保存，不加一次额外模型调用。选择风格能约束提示词整理，不能保证图像引擎完全解除原图身份条件；复杂混合用途仍需审核生成词和成品。
- 「动作时间轴」显示完整的源采样观察，包含末帧持有时间；生成用动作摘要与源观察单独记录。遮挡和快速运动仍可能看错，时间轴不是骨骼重定向结果。

## 安装与检查

从项目根目录，以已安装桌面依赖的Python运行：

```powershell
python -m tools.setup_local_intent --root D:/AIPicturesAssistant --data data
# 下载需要本机代理时可额外传 --proxy http://127.0.0.1:7897
# 可额外传 --modelscope，使用Qwen镜像但仍按原发布SHA验收
python -m tools.probe_local_intent --output data/acceptance/intent-text --brief "画一个俯视的红色玻璃药水瓶，不要文字"
python -m tools.probe_local_intent --output data/acceptance/intent-motion --kind animation --reference C:/path/character.png --motion C:/path/motion.gif --brief "保留人物外观，模仿动作参考，保持参考镜头与节奏"
python -m pytest tests/test_local_intent.py -q
python -m tools.verify_intent_ui
python -m tools.verify_intent_live --output data/acceptance/intent-live
```

安装只写未验收配置。真实识别的模型、素材用途、时间轴、路由与提示词检查通过后，才将 `data/local-intent-settings.json` 的 `validated` 设为true；协议测试或界面样例不能作为模型质量验收。

本机已实际测试文字道具、黄色角色改梦核场景，以及紫发角色＋快速挥爪GIF。前两类保留了目标内容与改动；跨物种样例经校对能转成人的手臂描述，不再把猫爪写进成品词。快速交替动作的单手/双手与时间边界仍会误读，不能视为精确复刻。这一轮验收的是识别、编辑、分流和界面连接，没有重跑耗时较长的完整H3生成来宣称画质提升。

界面采用固定双栏和「单张图片 / 动画」两个标签，参考控件在「单张图片」，参考动画在「动画」页顶部，提示词在弹窗中，任务只在左下方。主画面的流程引导、识别摘要、重复路径、种子提示和debug入口继续移除。内部参考图观察、方案及诊断记录仍存本地；显示名称为AlI，旧Python包/仓库/数据位置保留兼容。

分析记录保存在 `data/intent/<时间标识>/`，包括原需求、时间戳证据、原始结构化响应、验证后的方案和本机日志。不会写完整base64请求；后续生成任务另存 `intent-plan.json`，关联实际方案。Key不参与本地识别。正常使用重新打开 `run.bat`。

## 验收范围与限制

检查：纯文字图片不虚构参考；参考编辑不取消明确的风格/视角变化；角色图和动作素材用途不串用；GIF原延时/PNG顺序保留；生成类型一致；非完整JSON/未知素材引用/越界时间拒绝；手动提示词不覆盖；取消只退出自己的引擎；识别后再执行原生成队列。

参考图模型仍可能误读外观与自定义用途，需要审核提示词。动画内容不再由该助手识别，实际参考直接进入H3。手填时间轴是文字指导，不是精确关键帧或骨骼重定向；当前生成器一次使用一张外观图与一份动作素材，不宣称支持任意数量参考图联合约束。

提示词准确不保证生成结果精确，负面词也不是硬约束；某些图片路线没有独立负向条件，依旧沿用该路线的软性排除实现。不能宣传识别/画面达到100%准确或任意首尾无缝。

资料：[官方模型与本地部署](https://huggingface.co/Qwen/Qwen3-VL-8B-Instruct-GGUF)、[llama.cpp多模态接口](https://github.com/ggml-org/llama.cpp/blob/master/docs/multimodal.md)。
