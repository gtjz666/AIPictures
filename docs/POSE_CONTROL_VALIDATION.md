# 后台姿态约束验证

用户已确认先验证后台姿态／轨迹方案。这次许可仅改变“不读取动画内容”对结构提取的限制：不生成动作文字、自动时间轴，不恢复旧 Wan/骨骼编辑入口。通过输入和实际生成质量核对之前，不设为软件默认功能。

## 路线与验收门槛

现有 Ref2VA 的 RGB 参考条件不等于逐帧关节控制。候选采用[官方 H3 Fun ControlNet](https://raw.githubusercontent.com/Comfy-Org/docs/main/tutorials/video/minimax/minimax-h3-fun-controlnet.mdx)真正的控制分支，不把骨架图片当作普通参考视频后便声称完成了姿态约束。

1. 输入检查：在同一份冻结 GIF 的少量关键帧上提取结构，叠回原图核对手腕、脚踝、肩髋与侧别。分数高不代表位置准确；衣裙遮挡处不能冒充人工真值。不用插值、阈值放宽或补造关节掩盖失败。
2. 连续性和体型检查：短片内缺点、跳点及左右互换必须检查；Q版短肢向长身材转换不能只按整幅图拉伸。单帧合格不等于这一步通过。
3. 运行检查：控制分支和基座格式匹配，保留原有分阶段编码／采样。新增分支的内存、显存及退出行为需要真实验证，不能从文件大小推断本机可用。
4. 成片检查：保持角色／素材／种子／片长／尺寸／步数一致做对照；看实际动作时刻、脚部和双臂，而不只看任务成功。未通过时不向普通界面开放。

## 可复现探针

`tools.probe_pose_control`：仅 CPU ONNX，使用已保留 DWPose 权重及安装的 controlnet_aux 原始预／后处理函数。明确使用整图框，适用于这次单主体诊断，不冒充已验证的自动人物检测。只在显式命令下运行，无联网下载、无 H3 启动、无 UI 改动。

`tools.probe_sdpose_control`：复核官方模板使用的 SDPose。复用私有 Comfy 环境和官方节点，默认 CPU、单张处理；只有显式 `--device cuda` 才使用显卡，启动前以标准库检查本地队列，忙或状态不明时拒绝。其他端口须通过 `--backend-url` 指定。不启动服务、不加载 H3，不覆盖活着的 GUI 的任务上下文。两个探针保留模型与辅助源码校验值、输入 SHA、源 PTS、原始关节分数和实际叠图；输出目录存在时拒绝覆盖。

本机路径和实际结果在 `.agent/STATE.local.md`；验收目录为 `data/acceptance/pose-control-20261108/`。依赖只放该目录的独立 CPU 包文件夹；SDPose 权重单独保留并记录发布方 SHA，不改 H3 环境或启用普通功能。

## 已确认的兼容范围

官方控制分支支持 Ref2VA。核验发布树及 safetensors 文件头：v1 的量化 pruned/convrot 文件为 2,296,635,360 字节；控制模块和现有基座的调制层均是 `[96768, 8]`，匹配 adaln 曲线形式。没有下载完整控制权重；此项只是文件和接口核对，不是加载、显存或画质验收。v2 更大的控制分支未纳入本轮。

## 当前结果

DWPose 已运行8个源画面和1个目标立绘：源画面每张12个肢体关节中仅1–6个达到官方0.3绘制阈值，8张的双肩／双髋均缺失；叠图还有膝位偏到裙身的情况。目标立绘则12个肢体关节均达到阈值。**本例源输入不通过，不能直接用现有 DWPose 接入。** 这不是通用检测准确率，也不解释历史黑屏。

SDPose CPU复核0、0.8、2、4秒与目标立绘，5张均检出12个达到阈值的肢体点。逐张回看叠图，举手、抬脚和交叉手臂的大致位置比现有 DWPose 完整。单张耗时111–142秒，不适合直接用于整段交互。

CPU结束后，显卡独立处理前4秒40张真实源帧与1张目标图，共77.12秒纯提取时间，源帧中位数1.64秒/张。38张源画面12个肢体点达到阈值；0.1、0.2秒的右手腕分别只有0.156、0.186，属于遮挡漏点，不补造。CPU/GPU共有的0、0.8、2秒，17个身体点最大位置差小于0.08像素。回看12组代表画面和最大相邻位移的3.7→3.8秒原图：大幅手部位移确实存在，不能把真实快速动作当作识别抖动并平滑掉。没有人工标注的完整真值，不把这些分数当作准确率或保证全片无左右互换。

GPU进程19:36:44–19:38:38正常结束，原记录器在对应窗口116次采样、查询错误0，设备总显存采样峰值约4.87GiB，退出后约1.53GiB。该数值包含其他显示/进程使用，不是单进程精确峰值；仅证明本次姿态提取阶段运行，不证明增加控制分支后的H3稳定性。首次显卡启动尝试在导入桌面客户端时因私有环境没有websocket而失败，尚未导入Torch或推理；改为标准库只读队列检查后运行成功，没有向H3环境混装依赖或重试抽选生成。

## 验收结论及后续边界

**SDPose通过了本例少量帧/前4秒的基本提取可用性检查，整条动作约束路线尚未通过接入验收。** 当前完成的是结构提取和运行成本验证，没有新的H3成片、没有完整控制权重加载/体型重定向，也没有真实生成精准度提升证据。

根据检测到的二维关节按画面高度归一化，目标/源中位数的比例系数约为：躯干1.57、上臂1.88、前臂1.90、大腿2.04、小腿2.54。它们不是三维骨长真值，但足以说明不能将这段Q版骨架统一拉伸后直接当作目标角色控制。手接近脸、双手接触等关系也不能仅凭拉长各段骨骼保证；需要体型重定向、遮挡策略及同设置短片成片对照。验证前不下载/加载更大的控制分支、不将未验证选项放入普通软件。现有手填动作表与提示词流程保持不变。

证据：`sdpose-keyframes.png`、`dwpose-cpu/body-overlays.png`、两种提取器的`extraction.json`、`sequence-metrics.json`、`proportion-audit.json`、`gpu-window.json`及模型收据。4项专门检查验证忙/异常队列拒绝、超时不当离线、远程URL拒绝、非均匀GIF呈现时刻保持原帧无混合；两个解释器语法检查通过。没有修改应用运行逻辑，不将旧软件全量测试冒充本轮验收。
