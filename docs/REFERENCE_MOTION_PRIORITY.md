# 参考动作优先生成（2026-11-06）

复杂GIF的逐段识别仍有误差。此前「自动生成提示词」已默认只整理外观并要求跟随实际动作素材，但「分析动作」的自动时间线仍被标成强制时序；实际Ref2VA提示词还要求全身入镜、不得切镜或突然缩放。两处文字都可能与真实视频冲突，不能把它们当作准确的动作真值。

## 本次实际改变

- 真实视频、GIF或PNG序列继续作为Ref2VA的独立视频输入，角色图作为独立图片输入。生成提示词明确：动作顺序、节奏、停顿、重复手势、幅度、方向、表情和镜头以实际视频为准。图像的静态站姿不限制动画，取消参考路线的固定全身/固定镜头要求。
- 「分析动作」仍按按钮触发，并保留可编辑时间线。程序生成且未经修改的动作行只供核对，不再送入生成要求。用户修改的行按输出时间单独提交，仅覆盖相应范围，其余动作跟随真实素材。时长改变时，对比原始分析覆盖范围，不能把未修改的裁剪行误当成人工修正。
- 用户直接改写正向提示词时，保留可见文字；删除或替换的时间线不能在后台重新出现。无动作参考时，原来的文字动画和时间线逻辑保留。
- 已组装出观察时间线时，外观提示词整理阶段不再接收不确定的动作/镜头概括，避免它们再次变成强制正反词。分析结果仍存于记录和界面。模型指令要求反向词只补充结构/外观异常，不凭空排除停顿、重复、转身或近景；用户排除词原文保留。没有额外模型调用。
- 右侧选择的参考图用途在入队时冻结到任务：人物/外观、仅风格或自定义用法。风格参考不强制复制图片人物，自定义不默认锁定身份或站姿，缺少用法文字时阻止入队。

`job.json`中的`user_prompt`保留界面原文，`prompt`是整理掉未修改分析行后的实际要求；`motion_analysis_timeline`保留供核对的整表，`motion_timeline`仅含手动修正段。`motion_prompt_policy=reference_first_v1`标记本规则。`prompt.txt`与`workflow.json`保存实际进入编码节点的完整提示词，便于以后比较。旧任务不批量改写。

## 模型接口与限制

本机安装的官方`MiniMaxH3ReferenceToVideo`使用`<Picture 1>`与`<Video 1>`引用分别输入的图像和视频，保留视频VAE及文本编码两个条件路径。[官方节点实现](https://github.com/Comfy-Org/ComfyUI/blob/master/comfy_extras/nodes_minimax_h3.py)与本机源码已核对，本次未更换节点、模型、采样参数或精度。

“最高优先级”是对模型的语义说明，没有冒充一个可调的数值权重或硬约束。它能去掉已确认的文字冲突，不能保证逐帧复刻、解剖结构之间无损转移或复杂手势识别准确。不要把程序测试通过称为真实生成画质改善已经验证。

本次没有运行新的GPU推理、生成或压力测试，没有下载模型/依赖。既有真实生成验收截图已回看，但原视频任务缓存已清除，不能据此做相同种子的新旧逐帧质量对比。待可正常生成时，可在相同素材、种子、时长与设置下比较动作顺序、节奏、幅度、镜头和目标外观；自动时间线只用于定位误差，不能同时作为判定真值。
