# 面向游戏开发者的本地美术工具路线

本轮已加入完整动作骨骼、可选手调、足部局部检查和任务显示。走路完成常规参数实测，其他动作仍需扩大验收。以下是后续实施顺序，不代表这些功能已经完成。

## 当前基础与缺口

已有独立 Windows 界面、本地 ComfyUI 调用、参考图、手动风格 LoRA、图像预览/保存、动作帧与精灵图/GIF、缓存清理和基础工作流编辑。已接入完整姿态序列条件；概率生成仍不能保证任意图片的肢体、鞋型和身份完全正确。

单张流程现在统一做前景分割，尚未形成物件与背景的独立生产流程。场景背景应保留整幅画面，不能沿用角色抠图策略。现有骨架以双足角色为范围；四足、翼类、无足和机械结构需要独立布局与验收，不能静默套用人体骨架。

## 下一步：先完成三类素材入口

| 素材 | 用户选择 | 默认产出 | 验收重点 |
|---|---|---|---|
| 角色 | 参考图或文字、画风、朝向、静态/动作 | 全身透明 PNG；动作 PNG 序列、精灵图、GIF | 完整入镜、身份与服饰、肢体和鞋子、全周期及地面 |
| 物件 | 物件描述、参考图、画风、侧视/俯视/近似等距、尺寸 | 居中透明 PNG | 轮廓完整、没有人物/多余物件、方向与比例 |
| 场景背景 | 场景描述、画风、视角、横/竖/宽屏、尺寸 | 保留完整背景的 PNG | 构图、透视、可用留白、遮挡与画面完整性 |

类型、画风和视角由用户明确选择。LoRA 保持手动选择，沿用现有兼容性标签，不增加提示词推测 LoRA 的步骤。各类分别使用中文默认正反词，避免把角色的肢体限制、抠图规则误用到场景。

单张 SDXL 的中文目前仍是有限词表。应增加可选的本地中文描述改写/翻译，与素材类型和 LoRA 选择解耦；用户原文、实际绘图提示词与缓存结果分别保存。这个模块帮助表达复杂物件和场景，不自动选择 LoRA，也不在图像推理时继续占用大模型内存。

实施上先增加 AssetRequest 的素材类型、视角、背景策略和质量选项，分别路由到小型工作流构建器；保留 ImageRequest 与现有工作流副本机制。后处理按类型选择“前景分割 / 完整画面 / 可选高清”，不能在界面之外隐式更换素材类型。

先提供一个经过实测的默认组合；更多视角与画风逐项增加样本验证。单靠文本实现的等距或多视角只能标为近似，不宣称几何与身份完全一致。

## 然后：把生成结果变成能导入游戏的资源

1. 每个角色/物件保存独立项目，固定参考图、配色、模型和工作流版本；新动作延续同一角色项目。
2. 统一画布、角色尺度、地面和枢轴，导出每帧时长、边距、裁切偏移与动作名称；PNG 序列和图集可直接复用。
3. 提供 Unity / Godot 导入示例和通用 JSON，不让本软件依赖游戏引擎运行。
4. 像素素材保留硬像素与整数倍缩放，非像素素材保持半透明边缘；不要把两类共用的抗锯齿设定写死。
5. 素材库按项目、类型、动作、风格与保存状态筛选。任务编号留在内部记录，界面使用素材/动作名称。

## 再扩展：一致性与批量生产

- 多角色、不同体型和遮挡的动作测试集；失败动作保留检查图，不用重复图片凑齐帧数。
- 扩展独立的双足、四足与机械布局。自动适配优先，手动校准为可选；不适用时明确报告。
- 角色前/侧/背视图与物件多视图需要经过验证的条件流程；先解决一致性，再开放批量。
- 背景分层、远中近景与无缝地图单独实现；前景分割不等于可靠的场景分层。
- 批量任务允许低分辨率预览、确认后高清重做，保存模型、种子与实际工作流；不用“自动检测通过”代替成品质量验收。

## 最后接入训练与视频编辑

当角色、物件、背景的输入到游戏导出流程稳定后，再接数据集筛选/标注与现有 LoRA 训练框架，训练环境与推理环境隔离。完整视频创作与游戏动作帧继续使用独立流程，避免把视频能力当成逐帧可控性。

## 动作参考与本轮设计依据

- [Wan Animate 官方 ComfyUI 工作流](https://docs.comfy.org/tutorials/video/wan/wan2-2-animate)：使用参考图与 pose_video 进行动作迁移。普通 I2V 工作流不能仅增加骨骼文件就获得姿态控制。
- [Blender Rigify 的腿部链与脚跟/脚尖控制](https://docs.blender.org/manual/en/latest/addons/rigging/rigify/rig_types/limbs.html)：参考腿、脚、脚尖和脚跟控制的职责划分；本项目提供自己的 2D 关节实现，没有复制 Blender 绑定系统。
- [Adobe 跑步周期说明](https://www.adobe.com/uk/creativecloud/animation/discover/animation-run-cycle.html)：跑步包含接触、承重、腾空等阶段，与走路采用不同动作预设。

五种预设是本项目的程序化动作，不是从上述网站下载的人物骨骼素材。骨骼约束与负向提示词都不能证明接近 100% 的普遍生成成功率，需按素材和动作公布实际样本、失败案例与适用范围。
