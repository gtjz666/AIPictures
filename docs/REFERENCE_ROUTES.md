# 文字与参考图分流：研究和实测

2026-11-02。当前默认是“自动 · 文字用 Z-Image / 参考用 FLUX”。原来的 Z-Image 图生图保留为手动“小幅重绘”，SDXL普通生成入口和已核验的SDXL检查点退役。H3动画和用户手选帧导出不变。

## 使用

1. 运行 `run.bat`，在“模型与画面”中选择默认“自动”，后台预设保持“自动选择”。
2. 没有参考图：描述人物、物件或场景，直接使用Z-Image文字生成。
3. 添加参考图：自动使用FLUX.2 Klein参考编辑。预览显示选中的图，上方标题和设置中明确显示实际引擎。描述需要保留的特征、目标画风和变化，不必填写隐藏的角色模板。
4. 移除参考图：下一次生成回到Z-Image空画布；不能残留原图。已经入队的任务仍使用入队时的图、提示词和实际种子。
5. 真正需要原图小幅改动时，可手动选择Z-Image并调整重绘幅度；手选引擎不会被参考图悄悄替换。FLUX也可单独手选。

没有相应组件/真实验收记录时明确不可用，不切回SDXL，不自动下载大模型。不自动运行分析模型、翻译或付费API。透明输出仍在完整RGB生成后处理；若要保留梦核场景，应选择“完整画面”。

两种蒸馏模型采用各自原生的CFG1路线，反向词只是自然语言软性排除要求，不能等同独立负向引导。重要的眼睛颜色、服装和目标材质应在正向明确写出。软件不会为了提高表面符合度而偷偷改写用户原文。

## 为什么不把FLUX参考节点直接接到Z-Image

- [Diffusers的Z-Image官方文档](https://huggingface.co/docs/diffusers/api/pipelines/z_image)提供普通图生图：参考图编码为采样起点，重绘强度决定修改程度。低幅度容易保留原貌，也容易压住新画风；高幅度会丢失身份细节。
- [ComfyUI官方FLUX.2 Klein教程](https://docs.comfy.org/tutorials/flux/flux-2-klein)分别提供文字生成、参考编辑和多参考工作流；[BFL模型卡](https://huggingface.co/black-forest-labs/FLUX.2-klein-4B)说明4B模型具备参考编辑能力。
- 本软件使用参考图→缩放→VAE编码→ReferenceLatent附加条件；输出从独立的EmptyFlux2LatentImage和随机噪声开始，四步原生调度。参考潜变量不替换输出潜变量。借鉴的是条件与输出分开的设计，模型必须训练过这种输入，不能靠搬节点给其他权重增加能力。
- 也研究了[Alibaba PAI的Z-Image ControlNet 2.1](https://huggingface.co/alibaba-pai/Z-Image-Turbo-Fun-Controlnet-Union-2.1)：轻量8步版本可控制轮廓/灰度，但轮廓控制不等同语义身份编辑。现有FLUX已通过同图实测，本轮没有为了试验再下载ControlNet或更新共享Comfy环境。

## 同图、同提示词的真实比较

输入为用户正面黄色角色PNG。统一832×1024、实际种子3588380392898739，使用用户原来的英文梦核正反词；模型使用各自原生步数。全程串行，本机加载/缓存情况会影响时间；表中不是普适速度承诺。

| 方案 | 实际耗时 | 目视结果 |
|---|---:|---|
| 原Z-Image重绘0.45 | 复用用户既有结果，未重复计时 | 主体基本不变，梦核背景/氛围不明显 |
| Z-Image重绘0.85 | 45.29秒 | 粉彩和朦胧感出现，但变成黄色服装的娃娃，角色身份失败 |
| FLUX直接参考 | 59.41秒 | 黄色角色、腹部/手脚大体保留，出现梦幻环境；眼色偏蓝、脚形与色彩有变化 |
| Z-Image文字风格图→FLUX双参考 | 86.00＋64.21＝150.21秒 | 同时把原图作为身份参考、Z图作为风格参考；无明显保真优势，仍偏蓝眼睛，背景增加小角色 |

只把Z-Image文字图传给下一步，会丢掉原参考图提供的身份依据。因此两阶段对照特意保留原图和风格图两张条件，是更有利于保真的候选方案。它仍未比直接FLUX改善，故不作为用户默认流程。代码保留多参考研究封装和复现工具，不强制每次多生成一张图。

本轮选择FLUX直接参考，依据是这组样本中角色保留与耗时的折中。不能据一张参考图宣称总体准确率或任何画风100%一致；梦幻不等于已经准确达到阴郁梦核，原正反词中的“略诡异/避免明快”仍执行不足。

另一次真实Qt验收使用中文描述，将同一黄色角色变为清晰线稿/赛璐璐、夜晚森林、紫色发光蘑菇：从点击、上传、实际推理、预览到另存约94.81秒。画风、夜景和绿色眼睛执行正确，保存与预览逐像素一致、原图SHA不变；边线更粗、比例和阴影有变化。这是不同提示词的额外检查，不与上表混算成准确率。

## 测试和复现

```powershell
python -m pytest -q
python -m tools.probe_reference_route --help
python -m tools.verify_flux_ui --help
```

`probe_reference_route`接受来源job.json、明确参考图、新输出目录和family。`--text-only`检查Z文字路线；FLUX可用`--style-reference`附加风格图。目录已有记录会停止；已提交任务须按原prompt_id恢复，不能重跑覆盖。`verify_flux_ui --family auto`通过实际Qt点击、真实后端生成、预览、保存和SHA检查验收，可用`--prompt-json`指定测试描述/尺寸/种子。

自动检查覆盖无参考/有参考分流、清除参考后无残留、队列冻结、手选引擎不被替换、缺组件不回退、FLUX智能队列的独立条件保留，以及SDXL路径/大小/SHA/共享空闲核验和硬链接空间去重。模拟协议检查不替代上述真实推理和目视检查。

高级编辑器的“当前草稿”也按同一参考路线构建，并先上传真实参考图，不加载文字分支或占位文件。普通参考输入已从旧骨骼分析模块拆出：仅做Pillow的Alpha合成，不再为了上传图片导入SciPy/旧姿态分析。线程堆栈确认原先冷启动曾耗时超过20秒；拆分后相关21项回归在7.38秒内通过，没有改变输入像素算法。

## SDXL退役

按用户明确要求删除发布方SHA一致的SDXL Base 0.9VAE和Juggernaut v9检查点。基础模型的两个路径原本是同一文件的硬链接，实际只计算一次空间；本机共回收约14.04GB（14,043,426,522字节）。

删除器只接收明确目录和逐个路径，不遍历删除目录；核验大小和SHA后，在每个文件删除前再次检查所有共享后端空闲。文件修改、路径重定向或忙碌时保留/停止。原图片、原工作流、ControlNet、IP-Adapter、CLIP Vision及其他模型保留。原SDXL安装器不再下载检查点，删除收据仅写本机data。
