# 静态参考图的结构优先生成

## 使用

精灵图→单张：图1放姿势／构图来源，图2放主体外观，填写“将图1中的人物替换为图2中的角色，保持图1的姿势和构图”。生成页的「姿势／结构来源」默认按需求选择，也可明确选择图片或关闭。提示文字会显示每张图的实际用途。先点「生成提示词」，检查下方稿件，再单独点「生成图片」。

当前结构路线支持一张结构图＋一张主体图；同一张图也可同时提供两者。不明确的分工可以手选结构来源；有额外参考图时会报明范围，不静默丢图。只换画风的已验证流程继续独立使用，自动选择不把风格图当主体。文字要求新姿势、却没有对应姿势图片时，不会把旧姿势强加给新要求。

改变图片、需求、结构来源或下方稿件后，旧的审核稿／处理中结果不能直接沿用。导入素材不自动识别；「生成图片」会提取已经选定的深度结构，不再运行语言模型分析动作。动画和CG没有新增未验证的关节控制开关。

## 实际工作流

1. 提示词整理仅观察主体外观图，取身份、衣着配色和画法；结构图不交给语言模型猜关节。丢弃助手观察字段中夹带的旧站姿／机位，绝不据此删用户明确修改。
2. 结构图片经独立CPU进程使用 Depth Anything V2 Small 提取相对深度。保留长宽比，按目标画布居中排放，远处填黑；不套用人体关节模板。
3. 提取进程退出后，模型输入1绑定深度图，输入2绑定主体原始RGB图。通过经过训练的 RefControl 4B depth 适配器接入模型采样路径，强度0.9；使用现有FLUX.2 Klein 4B四步流程。
4. 每个任务保留原图SHA、原始需求、可见稿／英文稿、结构来源、模型输入顺序、深度图与实际提交工作流。画廊编号与内部输入编号分开转换。
5. 结构组件缺失、提取失败、取消或中途更改时拒绝提交，不悄悄退回普通参考。CPU进程仅本次运行，取消只终止自有进程；不累积常驻识别模型。任务完成后沿用原来的空闲推理缓存释放。

这是学习过深度融合的结构适配器，不是独立ControlNet分支，也不是逐关节硬锁。采用深度是为了覆盖非人形几何、重叠和相对远近，避免将怪物或道具强套成人体。没有实现任意物体的逐像素部件命名、三维骨长真值或遮挡部位还原。

## 本机真实验收及限制

- 同种子、同512方形画布、同四步的人体低蹲对照：普通两图参考将一条腿改为抬腿；深度＋训练适配后，两膝外张、小腿内收及后仰躯干更接近源图。仅把深度当普通图片的对照也保留，不能把所有收益都归因于提示词。
- 非人形圆润卡通对照：两条路线都完成抱头，训练适配保留目标柔和画风更好。不据这一个样例声称动物／机械的通用精度已通过。
- 真实Qt按钮→只识别主体→中文可编辑稿／英文稿→单独生产→实际保存工作流已完成，使用导入后界面实际352×352画布。没有肢体文字重建，仍生成外张膝、内收小腿与后仰躯干；深度提取CPU约9.73秒，私有进程退出，源文件SHA不变，实际队列保留适配器。
- 首次界面提示词试验把外观图“正面站立”夹在style字段并复述图号，旧稿被拦截，未提交。随后分离结构专用编写规则、过滤助手事实中的姿势段、在编写前展开角色分工，真实最终流程通过。失败和中间结果保留。

手部接触、遮挡、脚形和比例仍会变动。人体样例由光脚灰模迁移到长袜鞋角色，鞋／脚不能逐像素重合；目前不能承诺精确换皮。主体与结构体型差异越大，越需检查输出。视频逐帧时序约束另行验收，本次不更改视频路线。

## 资源与复现

[RefControl模型卡](https://huggingface.co/thedeoxen/refcontrol-FLUX.2-klein-4B-reference-depth-lora)指定深度第一、外观第二，推荐权重0.8–1.0；主要在人类上训练。官方推荐undistilled Base约50步，本机只注册实际验证过的现有distilled四步配置，不将其他基座／大步数算作已测试。

[Depth Anything V2](https://github.com/DepthAnything/Depth-Anything-V2)使用Small模型。两个权重的发布版本、大小、SHA均固定在 `tools/install_structure_control.py`，下载约191.65MB；不升级Python环境。跨盘无法硬链接时会在共享Comfy模型目录另拷贝约92.43MB适配器。两个模型卡许可均为Apache-2.0；不将旧Woosh音效的许可混用到此路线。

安装器仅下载／校验，不自动注册validated。需要已有包含torch、cv2和官方辅助源码的独立解释器。验证后在本机忽略的 `data/structure-control-settings.json` 配置schema_version、validated、python、weights、aux_source、adapter、strength与proof。不要把本机路径、权重、源图或生成结果上传仓库。

- `tools.probe_structure_control`：空队列时显式运行对照，固定种子和尺寸，新目录保存全部结果，不自动重跑。
- `tools.verify_structure_live`：真实界面两步、真实文字模型和结构生成，保留源SHA、退出和实际队列证据。
- `tools.verify_structure_route`：无模型的界面协议检查，验证实际排队工作流、结构/外观分别上传和中途改变来源后拒绝旧任务；不能冒充画质验收。

具体本机证据位置、成功与失败目录以及后台任务见 `.agent/STATE.local.md`。
