# 准备进度、取消和关闭窗口

准备参考、编码连续姿态、加载模型时，ComfyUI 尚未提供采样百分比。动画起始阶段改为活动进度条，明确显示阶段和持续耗时；收到真实采样事件后再切换到百分比。当前任务下方直接显示完整阶段，无需将鼠标放到任务名称上。

取消按钮立即设置任务取消标记，并通过独立后台请求发送当前客户端已提交任务的取消。节点尚在执行或原进度连接正在等待时，也能发送控制请求。控制请求使用 2 秒的单次读取超时，只针对记录中的任务标识，保留队列确认后再开始下一任务的约束。

窗口关闭不再以“后台线程仍在运行”为理由拒绝退出。关闭时记录任务标识、取消标记，停止后续界面回调，交给一个独立小进程尽力发送本客户端的取消请求。此进程不加载模型、不新建 ComfyUI，也不终止共享后端。ComfyUI 原始输出、模型和工作流保持保留。

GUI 工作线程改为可脱离的守护线程，通过 Qt 信号回传消息，避免在仍运行的 `QThread` 析构时崩溃。应用退出时若本地原生计算仍未返回，结束本 GUI 进程，独立取消进程继续工作；尚未完成的缓存帧可能不完整，不能把它们标为已完成资产。

这保证取消和关闭操作响应，不代表能强制即时中断任意 CUDA / 原生编码节点。后端需要在可中断位置响应取消；确认前不会叠加下一个生成任务。窗口已关闭的记录见任务目录 `window-closed.json`，取消发送记录见 `data/last-close-cancellation.json`，提交标识也提前保存在 `submission.json`。

验证：`python -m tests.live_cancel_close` 检查忙碌显示、独立取消、只取消本客户端、关闭后无迟到界面回调；`python -m pytest -q tests/test_worker_exit.py` 在独立进程中模拟持续 60 秒的原生阻塞调用，验证进程仍能关闭。
