# MOSS 排版生成与参考图编辑

2026年11月17日。独立工作流，不改变现有图片、动画、音频或Godot蓝图的默认选择。

## 能做什么

软件顶部“画面设计”打开独立窗口，提供两条路线：

| 模式 | 输入 | 输出与用途 |
| --- | --- | --- |
| 排版生成 | 手写整体描述，文字／物体／人物区域、文字内容及位置 | PNG；游戏标题画面、菜单、图文说明、道具展示 |
| 参考图编辑 · 社区扩展 | 1～4张静态参考图、手写图片用途与修改要求 | PNG；尝试改变画风、服装、颜色、动作等；当前作为实验功能 |

官方MOSS-Image Base／SFT原生能力是文生图和布局输入。参考图编辑额外使用chinoll的Moss-Image-Edit适配器，不把它称为官方基础模型已经原生支持的多图编辑。作者说明支持最多4张参考图；本机实际验收是双图，尚未对全部四图组合做质量验证。[官方SFT说明](https://huggingface.co/OpenMOSS-Team/MOSS-Image-SFT)、[编辑扩展作者说明](https://huggingface.co/chinoll/Moss-Image-Edit)

布局框控制元素大致放置区域，不是关节骨架、部位遮罩或像素级边界。编辑布局后会重新生成一张图片，输出不是PSD或已经分层、可直接编辑的UI组件。

## 排版生成步骤

1. 打开“画面设计”，选择“排版生成”。
2. 填写整体画面提示词。只使用用户手写内容，没有自动图片分析、需求改写、翻译或额外语言助手。
3. 添加“文字”“物体”或“人物区域”。拖动区域调整位置，用X／Y／宽／高调整大小。
4. 文字区域填写实际需要显示的文字；区域描述填写字形、颜色或物体外观。
5. 修改输出尺寸时，区域坐标按比例缩放。导入的布局草稿必须与画幅一致。
6. 点击“生成图片”。结果显示在窗口下方，可另存，也可“用于软件预览／导出”，再走现有图片与Godot组件导出入口。

“保存布局”保存可再次编辑的JSON草稿。“导出工作流”保存ComfyUI API JSON，便于检查实际节点与参数。它不是参考图片，也不会把排版稿自动解释成骨骼控制图。

![实际布局生成样例](images/moss-layout.png)

本机样例：1024×1024，固定种子20261117，25步。主标题“星界远征”、中央宝石、“开始游戏”文字均出现，位置大体符合输入区域。这是单个样例，不代表所有文字、长段排版或多元素都能完全一致。

## 参考图编辑步骤

1. 切换“参考图编辑 · 社区扩展”，拖入图片或点击“添加参考图”。
2. 窗口展示编号参考图。删除图片后其它编号保持不变；再次添加会使用空位，提交时按当前编号映射一次。
3. 如需完整人物，选择主体参考图，点击“采用所选图片比例”，输出约100万像素；比例依然可以手动修改。
4. 手写各图用途，例如：“保留图2人物的外形、服装和画风，采用图1的动作与表情，只生成一个人物，全身完整。”
5. 点击生成并检查结果，尤其是主体是否串用、动作接触位置、服装与脸部细节。

不会将图片转成一段自动分析描述再代替用户要求。原始参考图保留；实际模型输入先按EXIF方向准备副本，透明区域合成白底，再等比缩放。

首版参考图合计约100万像素：1张约100万、2张每张约50万、4张每张约25万。输出暂限约110万像素，布局生成支持约26万～200万像素，宽高都须为16的倍数。这是针对本机12GB显存配置的保守范围，不是模型本身的完整分辨率上限。

本机双图测试以“黄色卡通角色动作／表情＋紫发人物外观”为输入，832×1248、30步、CFG4。预算调整后的生成约116秒完成：出现单个紫发人物、双手举到头部两侧及张嘴惊讶表情；手的位置未精确贴合头顶，发型、鞋和服装细节也有变化。不能据此承诺精确换皮、像素级身份保持或任意复杂动作复刻。

原先每张参考图约100万像素的双图配置，采样首步长时间未完成；已停止自有测试并保留失败记录，没有把该配置投入普通界面。后续使用上述总像素预算。这个现象不构成电脑黑屏或硬件故障的根因诊断。

## 模型与运行方式

只保留一套MOSS SFT量化基座，布局和编辑共用，不另装Base或未验证蒸馏版。合计约13.3GB：

| 文件 | 作用 | 大小约 |
| --- | --- | --- |
| moss_image_sft_int8_convrot.safetensors | 图片扩散模型 | 5.41GB |
| qwen3.5_9b_w4a8_gptq.safetensors | MOSS原生文字编码器 | 7.34GB |
| flux2-vae_small.safetensors | 图片编解码 | 0.25GB |
| moss_image_edit_lora_rank_64_bf16.safetensors | 社区参考编辑适配器 | 0.30GB |

文字编码器是生成模型的必要组成，不是之前删除的自动提示词助手。工作流没有TextGenerate、提示词增强器或自动视觉描述节点。

模型下载固定为Comfy-Org/MOSS-Image的revision 2929efe3cdd506c0a430bcfca70a9a8d805cc095，逐文件核验发布方SHA256；ComfyUI核心固定为c1eece62cbf1805d4f64286d7f5592e6a215e6ba。单独建立MOSS运行目录，复用现有推理依赖；没有升级原有ComfyUI、Torch或其它模型环境。[Comfy官方打包与工作流](https://huggingface.co/Comfy-Org/MOSS-Image)

生成分三阶段：编码提示词／参考图并保存条件 → 编码进程退出 → 扩散采样并保存潜变量 → 采样进程退出 → VAE解码 → 解码进程退出。条件以safetensors及JSON清单保存并校验，避免模型常驻累积。软件内MOSS任务与主队列串行，发现其它本地后端正在生成会拒绝启动，不中断共享任务。

取消只停止本次拥有的进程。失败保留目录、实际请求、模型校验、阶段工作流和提交ID；不会对相同任务自动重试，也不会悄悄切回其它图片模型。

## 工作流参数与坐标

| 路线 | 默认参数 |
| --- | --- |
| 排版／文字生成 | SFT，25步，CFG2.5，er_sde／simple，负分支第22层跳过，区间0～0.5 |
| 参考图编辑 | SFT＋编辑LoRA强度1，30步，CFG4，euler／normal，第22层跳过，区间0～1 |

默认移位由固定版本的原生MOSS模型提供，值为5；没有套用旧插件的ModelSamplingSD3。参数参考Comfy-Org发布的对应原生模板，官方独立Python示例的50步／CFG3配置不是同一套界面预设。[官方Comfy说明](https://github.com/OpenMOSS/MOSS-Image/blob/main/comfyui/README.md)

可编辑草稿采用左上角像素坐标xyxy，包含width／height。提交模型的JSON采用画布中心为原点的像素yxyx，不带草稿width／height。例如1536×1024上的[176,224,800,864]转换为[-288,-592,352,32]；小数边缘向外取整。[官方布局格式](https://github.com/OpenMOSS/MOSS-Image/blob/main/USERGUIDE.md)

## 复现与安装

工具入口：tools/setup_moss_image.py，需提供指定版本ComfyUI源码压缩包和现有可用Python；模型目录和运行目录均单独指定。工具验证源码包SHA，下载后验证模型SHA，已有文件不匹配时停止，允许续传已经开始的同版本下载，不覆盖其它模型。

tools/probe_moss_image.py可分别执行layout／edit独立验收；tools/register_moss_image.py只在两种路线均有成品、模型一致且三个进程都退出后注册。配置中的validated表示本机执行通过，edit_experimental仍为true，不等于视觉质量普遍合格。

aipictures/resources/moss包含两份可移植ComfyUI API工作流和可编辑菜单布局。参考编辑的API示例需要在对应ComfyUI输入目录上传reference_1.png、reference_2.png。这些示例不包含用户的图片或账户配置。
