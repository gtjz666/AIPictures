# 按需求选择参考属性，以及H3-Image初步试验

2026-11-13至14日。研究记录，不是普通软件已实现的权重功能。当前默认模型不变，上一轮未通过的姿势分流候选不合入。用户最新优先级是：参考图／语言关系驱动的图片素材，其次是参考图或文字驱动的动画与透明素材导出；音效和长视频暂保留现状。模型最终按各项功能的实际效果精简。

## 用户提出的新路线

用户建议先理解需求，再只分析相关参考属性，最后以对应权重控制生成。合理的中间表示应记录：原文片段、保留／修改／借用、来源图、目标对象、属性、区域或部件关系、用户要求的强度、观察证据与不确定性。它不能只靠关键词命中：“体型”和“姿势”不同，“保留体态”要由完整上下文确定；否定、例外和多对象分工也要保留。识别置信度与用户优先级是两个独立字段，不能把猜测的高分当成用户授权。

只分析用户指定的属性，不默认把整张图重新描述一遍再塞进生产提示词。身份／服装、体型、姿势／接触、表情、颜色、材质、画风、构图与背景应分别分工；用户没有要求迁移的来源属性不能自动进入成稿。图像仍通过实际像素或特征输入生成器，文字主要表达编辑操作与图号用途。该方向需要与之前“将全部图号展开成具体描述”的策略区分，不能默默继续旧的全图描述。

## 权重必须有实际接收路径

空间蒙版回答“哪里”，不自动回答“只取该处颜色、不要形状”。颜色与画风也不是同一特征。跨体型或改变姿势时，还需解决源部件到目标部件的对应与空间变换；把原图同位置的热力图直接套在目标上会错位，非人形不能套固定人体模板。

现有程序的FLUX ReferenceLatent只追加参考潜变量，没有每图每属性的权重／蒙版参数。已用的RefControl深度适配器有全局LoRA强度，不等于身份、姿势、颜色和画风独立加权。不能在JSON里加几个数就宣称生成器使用了权重图。

[IP-Adapter](https://github.com/tencent-ailab/IP-Adapter)提供了分离图像条件与文字条件的训练路径；[InstantStyle](https://arxiv.org/abs/2404.02733)研究内容与画风解耦及注入位置。它们说明按属性分离条件有研究依据，但其既有SD／SDXL适配器不能直接装在FLUX或H3上。H3属性级空间控制需要匹配架构的控制分支／特征注入或经过验证的注意力改动，当前没有该项真实生成验收。

## H3-Image接口核验

[MiniMax官方模型卡](https://huggingface.co/MiniMaxAI/MiniMax-H3-Image)明确同一checkpoint支持文生图与多参考图编辑（最多16张），不是从视频抽一帧。它有专用图片DiT和图片VAE，使用H3的Qwen3-VL编码器；不能只把权重替换到现有FLUX图中。普通软件的画廊、需求、缓存和导出可以复用，生成图与模型组件需独立适配。

官方采样为6步、引导1，不支持原生反向提示词。[Comfy官方说明](https://docs.comfy.org/tutorials/image/minimax/minimax-h3-image)提供可关闭的扩写节点与多图编辑模板。本机原Comfy0.20.1、既有H3私有Comfy0.43.0没有新的MiniMaxH3ImageConditioning，因此本次创建独立源码／环境。新节点接收prompt、参考图片、VAE和画布；没有按姿势／颜色／画风分别加权的接口。本次先测试原生多图理解，不声称已经实现属性权重控制。

## 已冻结的首轮实验

关闭额外提示词扩写，使用事先冻结的简短英文编辑要求与明确的Picture编号。人物外观等不人工重新描述。三个案例分别是两图姿势／表情、两图反向非人形迁移、三图主体／画风／姿势分工；每组一个预定种子20261113，2048×2048、6步、CFG1、euler/simple。素材是已知压力样例，不是独立留出集；画布也与先前FLUX试验不同，不计算受控精度或速度提升比例。

本机复用既有约15.69GB量化H3编码器，新增官方Comfy发布的W4A8图片DiT约12.55GB与FP16图片VAE约1.17GB，固定发布revision、大小及SHA。只在新环境更新comfy-kitchen至0.2.41，原Torch、视频环境和共享服务不变。编码条件与采样潜变量按原始张量保存，编码、采样、解码各由自有进程串行执行并退出，降低模型同时驻留。透明参考仅在原画布上合成白底，不裁切或运行主体识别。

源码与文件收据、冻结计划、实际任务ID、失败日志和输出保存在本机。启动成功、张量完整与模型执行完成均不等于视觉质量通过；须逐项检查身份、部件数量、姿态／表情、目标风格与来源属性污染后再决定下一步。

## 实际结果与决定（11月14日）

共完成7张新图：三个分工案例，及其中一个案例的措辞／画幅对照。每个条件仅一个固定种子；后续对照是在看到早期失败后提出的探索，不是预注册的独立留出验收。全部失败保留，未用换种子挑图；也不能把这些图片当作自动分析器已经实现。

| 条件 | 人工复核 |
| --- | --- |
| 两图，简短姿势／表情用途要求 | 外观大体保留，抱头与惊讶未实现，腰侧多出一条手臂；拒绝 |
| 反向人物→非人形 | 手臂仍下垂，眼色、画法与比例改变；拒绝。源图本来就有幻想背景，不能将背景称为凭空添加 |
| 三图分别提供主体／画风／灰模姿势 | 大体低蹲与描线画法可见，但圆润目标变为明显人体比例；局部有效，体型保留不合格 |
| 两图，仅增加Subject分工与保留／修改逻辑 | 两个来源主体一起出现，人物仍站立；拒绝 |
| 同分工，另加人工核对的姿势／表情事实，2048方图 | 两手抱头、惊讶成立，外观大体保留，但小腿／鞋被裁掉；局部改善 |
| 同一文字，改为原图2:3画幅、1728×2592 | 保留完整主体并做出抱头惊讶；这个已知案例改善，手形和身份细节仍非精确 |
| 同竖幅，再增加通用“保留原可见部件在画面内”要求 | 同样保留完整主体和所需动作；比上一条件没有清楚可见的额外收益。两张PNG及RGB哈希不同，不能说是同一输出复用 |

后两张说明本机这套量化H3对“保留身份外观＋具体姿势事实”有可继续研究的局部能力。它们没有证明简单用途词足够，也没有证明非人形迁移、任意遮挡或身份一致性已稳定。仅根据这个结果就删除现用FLUX、启用H3作为默认，会超出证据范围。因此保留一套H3-Image候选继续验证，**没有注册validated或接入普通界面**。

三个阶段按原始张量保存／重载；7张成图对应21个唯一的成功阶段任务ID，编码条件的每个张量在采样保存前后逐字节核对一致，实际参考潜变量数量与2／3张输入一致，原图与准备图SHA未变化，成功进程均退出。第三组初次采样因会话中断没有输出，原后端不在、端口拒绝连接后，在新目录复用已校验编码显式继续；保留原任务与不可读提交记录，不推断为显存或硬件错误，也没有重做前两张。

记录的132.60、160.03、322.46（复用编码）、391.17、771.03、247.85、217.70秒均包含进程启动／等待等；案例间画布和提示词不同，第三组排除了原编码耗时。它们不是纯采样速度基准，不能用于宣称比现有流程快多少。实际H3配置为官方Comfy W4A8图片DiT＋已有NVFP4编码器，不将结论推广到所有精度或其他发布版本。

## 模型清理

用户明确要求删除未采用模型后，逐文件核验发布SHA、大小、最终绝对路径、独立链接和使用状态，删除未通过本机验证的Qwen-Image-Edit-2511及其专用编码器／VAE，以及此前无一致收益的FLUX Klein Base FP8。合计34,261,738,231字节（约34.3GB／31.9GiB），实测空闲空间增加34,261,745,664字节；微小差额可能包含其他文件活动。

当前共享后端离线，最初要求在线空队列的删除尝试未操作文件。随后明确使用离线路径：每次删除前重新成功枚举系统进程，确认没有本地模型引擎，再删除固定允许表内的4个发布原样文件。原ControlNet／IP-Adapter／CLIP Vision等未纳入此允许表；现用FLUX蒸馏版、Z-Image、共用编码器、视频、音效、去背景与深度组件保留。已删除候选不要因旧安装收据自动补下载。

本轮没有改图片生产入口、音效或视频生成器；透明动画帧导出沿用已交付实现。新研究工具语法检查、真实7图条件完整性审计和6项删除边界检查已完成；没有把此前的607项应用测试算作本轮重跑结果。

下一步优先验证自动的“需求分工→只观察所需属性→可审核编辑要求→实际图像条件”流程，以及未参与调试素材。需要记录体型与姿势的区别、保留／修改方向、对应部件与不确定性；不得将本次人工核对的抱头句子写成角色或动作专用运行规则。属性空间权重仍需真正的接收分支，不能把自然语言强弱或一个数字当作已实现的权重图。
