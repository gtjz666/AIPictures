# 透明处理顺序与对照测试

## 当前顺序

1. 用户参考图保持原文件不变。仅文字生成时，第一张角色图也保留原始 RGB。
2. 独立副本用于主体定位、DWPose / 双足骨骼适配。分析副本可以抠图；其清理后的颜色和透明度不再作为动画模型的外观输入。
3. `generation-reference.png` 从原始图片读取颜色与背景，仅沿用骨骼分析的统一画布、缩放和朝向。原图已经透明时，按原有 alpha 合成一次中性底色，避免隐藏的黑色 RGB 被模型误读。不再自动抠掉不透明原图的背景。
4. Wan 完成整段原始帧生成后，再逐帧处理背景透明度。原始结果保留在任务的 `video/` 中。
5. `frame_NNN/matte_native.png` 保存原生分辨率的透明帧。常规动画的校色和显示尺寸处理随后独立记录；显式像素素材导出读取原生透明帧。

完整骨骼动画、旧的自由 I2V 和静态骨骼参考的外观输入均使用此顺序。单张通用图片原先就只在生成完成后按用户选择去背景，保留此行为。

动画 `sequence.json` 记录 `generation_reference` 与 `transparency`：是否对推理输入分割、实际送入模型的图片路径、源图排版、每帧透明处理是否保留 RGB。旧任务缺少输入策略记录时，字段为 `null`，不会推断旧任务采用了新顺序。

这项修改不改写已完成任务。重启软件后，对新任务生效。姿态分析仍可能先执行抠图，但分析图不再回流到模型外观输入。

## 重复对照

在仓库根目录使用软件虚拟环境的 Python：

```powershell
python -m tools.compare_transparency_order --sequence "已有动画目录" --out "data/order-test" --execute
python -m tools.compare_transparency_order --sequence "已有动画目录" --out "data/order-test" --execute --repeat-baseline
```

第一条保留原模型、采样、提示词、固定 seed、输出帧数以及所有骨骼输入，只替换参考图读取内容。第二条在同一后端重新提交旧的预抠图输入，排除仅依赖旧缓存的影响。第二条应在第一条结束后执行。

不带 `--execute` 只准备输入和对照记录。下载中断后使用 `--execute --resume`，已完成的原任务不会重新生成；恢复第二组时同时添加 `--repeat-baseline`。

输出包括：

- `before-input.png`、`source-input.png`：模型实际读取内容的对照。
- `before-workflow.json`、`after-workflow.json`、`baseline-repeat/workflow.json`：可导入 ComfyUI 检查。
- `video/`、`baseline-repeat/video/`：两组真实模型输出与任务记录。
- `before/`、`after/`：相同周期位置的透明帧。
- `comparison.png`：四个动作阶段的原始帧 / 透明帧并列比较。
- `experiment.json`：seed、任务标识、输入差异、每帧 RGB 保留验证与人工检查提示。

`near_white_fraction` 只是前景近白像素比例，不代表缺色率；白色衣服本来就应当是白色。不得用该指标宣称接近 100% 准确。

## 检验与限制

2026-10-29 本机真实对照：同一参考角色、固定 seed `2776800848084959`、相同完整走路骨骼、20 步、原生 480×640。两组均实际生成 17 帧，分别取 8 帧做 BiRefNet 透明处理。16 张透明帧全部保持其生成 RGB 逐像素不变。已重新运行旧输入，并核对旧任务实际上传图片与旧分析图内容一致。

人工逐帧对比可见，两组前臂白色缺块、丝袜白斑与鞋部模糊仍然存在，未观察到这次顺序调整带来的明显修复。本参考本来就有透明背景，新旧输入的平均通道差约 0.135 / 255；这组结果不支持“提前抠图是本图缺色主因”，也不能代表不透明复杂背景的所有情况。后置抠图仍保留为默认，避免把未来的分割误差反馈给生成。

验证结果：144 项自动测试及 7 个子测试通过；真实 Qt 手动 LoRA、空参考图、已选参考图预览检查通过。真实对照与报告在本机 `data/workflow-quality/transparency-order/`，用户图片和测试缓存不提交到 Git。

```powershell
python -m pytest -q
python -m tests.live_style_controls
```

自动测试验证分析图被错误清空时生成仍读取原始颜色、原图半透明边缘只合成一次、原背景保留、左右朝向与骨骼一致，以及文字生角色不再提前抠图。界面测试验证空白参考图、主动选择参考与手动 LoRA 行为。

把去背景移到后面可以避免把分割误差作为模型输入，但不能保证模型生成的 RGB 本身正确，也不能补回模型已经画错的服装、肤色和鞋型。透明分割本身也可能误判主体区域，应检查原始图与透明图两者。

本次还独立试验了现有 Qwen 图像编辑模型对缺色帧的修复。试验工具 `tools/qwen_reference_probe.py` 可保留中文编辑指令，支持固定原始角色作第二参考图；它不是软件默认流程。初次实测补回部分缺色，同时改变了角色构图，尚未达到动作帧验收要求，因此没有接入默认动画后处理。相关原始工作流、结果与诊断图保存在本机测试缓存。未新增下载模型。
