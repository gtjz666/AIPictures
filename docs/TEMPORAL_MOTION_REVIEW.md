# 动作时间轴的连续观察

动作素材通过「分析动作」按钮处理，导入不会自动运行模型。原视频/GIF/PNG及其RGB、延时保持原样，下面的图像处理只用于识别证据。

旧流程最多取12张独立图片，再让全局文字规划器写最多8段动作。短周期动作会采样到相似姿势，规划器也可能遗漏结尾。本轮真实旧记录中，9.3秒参考只写到6.9秒、3.07秒只到2.27秒、13.79秒只到6秒。

现在最多保留64个带原始PTS的观察点，存入样本前先限制分析图尺寸，避免缓存大量原尺寸视频帧。用每组六张、共享一个端点的局部图组核对身体朝向、两侧上肢、脚和躯干状态；下半部另有同帧放大区域。图组不混帧，不作为生成资产。模型只填写有限的状态值，程序描述相邻状态变化并用源时间拼接，最后一帧延续至素材显示结束。合并相同的相邻说明，完整保留观察记录。

本机llama.cpp运行日志提示Qwen视觉定位需要至少1024个图像token；本地识别命令增加1024下限和2048上限。每次只送一个图组，避免将64张独立高token图一次塞入8192上下文。总体画面规划只读取简短分段概述，最终动作表由程序附加，不再由全局模型重新猜测或压成8段。无动作素材的文字整理仍沿用原流程。

对于边框颜色足够一致、下半部恰有两块清晰分离区域的素材，可读取两侧鞋底/足部的图像高度，补充模型漏掉的相对抬脚。只有满足严格条件才使用；复杂背景、遮挡、合并区域不强行判断。图像左右不等于人物解剖左右，鞋底高度也不证明地面接触或真实支撑脚。

源图明显改变、状态却无法可靠区分时，不再写成“静止缓冲”。动作表标黄并提示待核对。小幅手势、交叉遮挡、模糊实拍和完整步态仍有误判；它不是逐帧动作真值，更不代表接近100%语义准确。当前模型的这些限制没有通过增加采样彻底解决。

真实验收使用同一组原素材和原Qwen3-VL-8B权重，比较旧软件落盘记录。最终三个时间轴覆盖9.3、3.07、13.79秒；猫咪结尾背向变化得到记录，两个纯色背景素材补充了部分脚部高度变化。最终CPU几何补充复用了SHA及像素匹配的真实视觉响应，再实际运行文字规划，没有冒充重新视觉推理。没有重跑整段H3去声称动画画质提高。

原生视频API也做过GIF对照，但当前调用没有保留可靠动态信息，未进入正式路线。试验用FFmpeg按发布摘要核验后仅保留收据，已移除本轮安装的二进制和下载包；生产没有新模型或依赖。

同时减少普通创作的后台开销：高级工作流的内嵌浏览器按需创建；参考预览隐藏、主画面隐藏或窗口最小化时停止相应播放。它们是已验证的软件行为修正，不能据此声称系统黑屏已解决。
