# 参考动画驱动角色替换：工程研究（2026-11-05）

目标是把视频/GIF/PNG序列中的运动迁移给参考图中的角色，保持动作顺序、节奏和目标身份，并支持独立游戏素材导出。它属于动作迁移、角色动画或视频主体替换；不应把语言模型逐段猜动作当作唯一控制信号。

本次仅核对论文和官方工程，没有下载新模型、恢复退役Wan入口或运行GPU对照。论文效果和官方演示不等于本机12GB显存的速度、稳定性或泛化验收。

## 可借鉴的方案

| 方案 | 实际控制方式 | 对本项目的意义与限制 |
| --- | --- | --- |
| Wan-Animate / Wan2.2-Animate-14B | 角色图＋空间对齐的身体骨架＋隐式面部特征；角色替换另保留背景/遮罩，可附加环境补光模块 | 已有Comfy原生工作流，可借鉴把身份、身体、脸和背景分开。骨架不是全部信号；补光会有意改变画面色调，与“保留参考配色”需要区分。不能把普通视频模型加个骨架图就当成同等能力。 |
| Wan-Animate-2 | 直接读取驱动视频，去掉中间动作提取器；官方要求提示词描述外观和背景，不描述动作 | 最贴近减少人工动作文字和前处理误差的方向。仓库列出Base、蒸馏权重与推理脚本，蒸馏示例10步。默认配置面向8张A800，另测试2张A800的480P，不能据此承诺12GB笔记本实时运行。README单独提到的Lite不能直接等同于已发布蒸馏检查点；引用仍有TODO论文编号，未将其当作已核实论文链接。 |
| Animate-X（ICLR 2025） | Pose Indicator结合驱动视频CLIP运动特征和显式姿态，学习整体运动模式与时间关系 | 论文直接讨论人形骨架硬套拟人角色的局限，适合研究Q版、不同身材和拟人动物。其“通用”不等于所有真实动物/遮挡/快速GIF都能正确迁移，也没有本机速度结论。 |
| MimicMotion（ICML 2025） | 带置信度的姿态指导、区域损失；长视频使用渐进潜变量融合 | 可借鉴低可信关键点不强控，而非对抖动骨架一律相信。项目注明VAE解码需要16GB，可转CPU；不能直接当作比现有路线更省显存、更快的替代。其潜变量融合不应用于本项目精灵PNG导出后的帧间混合。 |
| AnyCharV | 姿态＋目标场景/遮罩的主体替换，训练时从精细遮罩过渡到粗遮罩 | 有助于理解如何减少原角色轮廓、衣物残留并保留新角色细节。两阶段是训练策略，不代表每次推理必须生两遍；工程还需要SAM2等前处理，不适合无条件叠加到每次生成。 |

## 当前采用的流程

默认有动作参考时，将实际源帧交给现有H3 Ref2VA，文字整理只处理外观、风格、替换关系和明确的修改；不强制先识别完整GIF，更不默认同时加载语言、逐帧视觉和骨骼模型。详细动作分析仍由按钮显式触发，可用于有意改变动作或检查结果，分析模型先退出，再生成。

“只换角色、不变动作”是任务约束，不是100%复制保证。当前H3集成没有已验证的独立骨架条件接口；不能把DWPose渲染图直接替代当前参考视频并宣称获得姿态控制。若研究专用骨骼路线，应使用为该条件训练的模型、保留面部/遮挡信息，并先比较收益，不重新开放旧手工骨骼模板。

动作分析的原始证据保留源PTS；界面、编辑后的提示词和任务参数统一到输出时间。非循环按起点截取，源耗尽后保持最后真实帧；循环按源时长回绕，不拉伸动作速度。已分析后改变起点/循环方式需要重新分析，原编辑内容保留并阻止带旧时序入队。

新任务生成后先预览完整动画。普通H3原生RGB采用按需读取，不提前写全套PNG或重编无损视频；参考路线保留后端必要的原生PNG，但把额外视频编码推迟到导出。用户点击“导出”后选择完整视频或动画帧/精灵图，只有后者进入选帧、透明背景和素材处理。模型必须进行的VAE解码不能移到导出之后。没有原生RGB的少数旧式视频返回仍需解码准备预览，不冒称所有后端都完全不拆帧。

新任务只交付请求范围内的源帧（4秒/24FPS为96帧），原生采样可能为对齐多算尾帧，原始数据仍保留；不改采样帧数、不插帧、不融合、不降画质。历史任务保持原记录，不批量重写。

## 后续候选验收

使用用户提供的人物、Q版女仆、猫、拟人浣熊和目标角色，分别测试同物种、跨身材、跨物种、快速手势、遮挡、运镜。固定输入、目标时长和画布，记录身份/配色、动作顺序/节奏、背景泄漏、峰值与总耗时等独立指标；硬件观测仅在用户再次授权相应实测时进行。先验证当前H3直接参考方案，再与一个候选比较，不将多个大模型串成默认长链。

当前黑屏未稳定前不自动发起GPU验收。此次研究不能作为模型换型、12GB可用性或画质达标的证据。
