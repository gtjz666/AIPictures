# 共用 ComfyUI 与动画重影排查

## 连接行为

有 Comfy Desktop 时先打开它，再启动 AIPictures，或点击“启动 / 重连”。软件识别 Desktop 实际运行的 Python 服务端口，API、模型发现、上传、队列、下载、工作流编辑器都使用这个地址。常规 8188/8189 连接优先复用 Desktop；用户明确填写的其他端口保留。已有本软件任务排队时不自动切换服务。

“连接与显存…”显示实际地址；高级工作流也显示“当前引擎”。没有已打开的服务才启动独立 8188。`start-comfy.ps1` 也检测 Desktop，并通过命名互斥避免多个本软件启动脚本重复启动；不会阻止用户以后从其他软件另外启动 ComfyUI。

编辑器隐藏时不加载完整网页。打开后展示同一服务；动画图准备完成就同步实际节点，不必等动画结束。节点类型相同但连线变化时也重新载入实际连线，不仅修改提示词输入框。

旧版窗口需要重新启动 AIPictures 才加载新逻辑；无需关闭或重新安装 Comfy Desktop。旧缓存不会自动重新生成。

## 已运行的本机合并

本次确认两套服务均无运行/待处理任务后，保留 Desktop 的 8189，只停止明确符合本软件原始启动配置的 8188 监听进程；没有退出 Desktop、删除工作流或取消用户任务。连接设置更新为 8189。之后现场仅有 8189 在监听。

诊断脚本 `python -m tools.unify_local_engine` 默认只预览，`--apply` 才处理。它再次检查双方队列、服务身份和监听进程，遇到任务或身份不符便保留服务。脚本只面向当前旧本机启动配置，不是通用进程清理工具。

## 重影的两个层面

用户最新 16 帧缓存的原始 RGB 已能看见多层手指/轮廓，不能归因于播放控件。预览每次重绘棋盘底色后只绘制当前一张帧，没有叠加前一帧。

发现原动画导出复用了参考图的“实心内部填补”：半透明区域只要进入主体连通区深处就会被填到 Alpha 255。这会把本来较弱的边缘残影实心化。现在动画帧只清理孤立噪点，保留原分割 Alpha，不再应用参考图内部填补；参考图处理保持原规则。

实际模型条件改为 Wan 官方预处理 v2 的原生分辨率细线/细点尺寸。可见手指只使用有足够可信度的参考关键点，不再为遮挡侧复制另一组测量手指；完整身体链和双侧手腕仍保留。自动附加清晰瞬间定格、单一肢体轮廓的要求。全周期帧数、分辨率、步数、模型精度没有因这些修复降低。

这些改动解决了已定位的条件/导出问题，不等于能够用后处理重建原始 RGB 中的畸形手部。禁止把删除可见肢体、透明阈值切断手脚或锐化多层轮廓当作几何修复。

## 验证与限制

单元检查覆盖：保留动画半透明区、遮挡侧不克隆手指、骨骼旋转、后端发现、取消后空闲缓存释放及其他任务保护。`python -m tests.live_shared_backend` 实际加载 Qt/ComfyUI 前端，验证 API 地址与页面一致、隐藏编辑器不加载网页、同类型节点换线后快照一致；不提交 GPU 任务。

`python -m tests.live_ghost_revision` 是当前本机参考专用的诊断脚本：8 导出帧、17 姿态输入、20 步、不使用加速 LoRA。只在队列空闲时开始。2026-10-29 按用户要求移除内存与温度采样，以及对应的取消阈值；下方取消记录描述的是此前的测试版本。

本次先后两次真实提交都未完成成品验收：第一次在系统提交使用约 98% 时主动取消；关闭重复后端后第二次仍触及剩余提交额度保护，自动取消。第二次采样最高温度 76°C，没有得到完整新序列，不能宣称重影已经被模型验证消除。原始旧序列、姿态输入、提交记录和取消原因均保留。详见 `docs/VALIDATION.md`。
