# 逐帧骨骼、动作自然度与颜色校验

## 怎么使用

在“角色与生成…”选择动画类型、导入参考图，再打开“动作骨骼…”。上方和画布均显示 **第几帧 / 总帧数 + 当前动作阶段**。下方帧卡带骨骼缩略图，点击切帧；圆点表示该帧已修改。也可用时间条、上一帧/下一帧或方向键定位。

拖动关节后点 **播放完整动画**，从第一帧预览整个周期；可暂停、停止回首帧、循环和调整预览速度。播放使用刚修改的关键帧与插值，不提交 AI 任务。选择帧或开始拖关节会暂停播放，避免修改错帧。预览速度不改变导出 FPS。

“骨骼 + 人物示意”显示按参考取色的简化人物，帮助观察重心和肢体关系；可切到“仅骨骼”。“参考图底图”是静态对齐参考，可关闭。**人物示意不是参考图片的完整绑定，也不是 AI 成品预览**，不会补画遮挡纹理。保存后重新生成，才得到实际动画图片。

基准骨架修改会重新计算整个周期；动作帧修改只改变对应关键帧。自动生成默认使用新预设；旧的手动关键帧继续保留，想采用新预设可先“恢复自动周期”，再按需调整。

左侧当前任务下方显示持续更新的 **已用时 + 当前阶段**，模型加载或采样进度暂时不变时计时仍更新。完成、失败、取消后冻结为本次耗时；下一任务重新计时。动画缓存的 `sequence.json.timings` 分别记录参考准备、姿态输入、推理等待/下载、透明处理、颜色处理和打包耗时，不把它们混作纯采样速度。

## 动作调整

走路增加接触、承重、经过和推离阶段的重心起伏；肩胯反向配合，头部适度缓冲。跑步有前倾、屈臂、蹬地和腾空，躯干跟随受力；待机有轻微呼吸与手臂延迟；伸手加入重心前移与屈肘过渡；跳跃保留下蹲、起跳、空中与落地缓冲。移动骨盆后重新求腿部 IK，保持骨长；待机与伸手的脚踝保持在原位置。

参考 [Monmouth 动画课程](https://animation.monmouth.edu/instruct/animation/walk-cycle/)中完整左右周期、承重/经过位置及重复终点处理的说明，采用本项目自己的程序化动作。它不是自动理解任意体型的动作捕捉系统，复杂遮挡、非双足和短腿角色仍可能需要手调。

## 生成参数与耗时

之前把普通 I2V 的 CFG 3.5 沿用到 Animate，现改为 Animate 官方的 **20 步、CFG 1、shift 5**，保留 480×640 原生推理、17/33 姿态帧、原模型精度和原生 VAE 解码，不启用快速诊断 LoRA。[官方配置](https://github.com/Wan-Video/Wan2.2/blob/main/wan/configs/wan_animate_14B.py)

CFG 1 通常省去负向分支的模型计算，不能再把它描述为与高 CFG 相同的反向引导。软件保留原反向文本与节点用于记录，同时把常见排除项整理成简短正向生成要求，自定义排除内容也随实际提示词保存。这是固定文本规则，不调用语言模型，不选择或分析 LoRA 类型；不保证所有自然语言要求都准确实现。

改动不是减少步数或分辨率。12GB 显存仍需卸载 14B，CPU BiRefNet 也需要时间；实际耗时以每次记录为准。预览复用参考纹理和帧卡，播放不反复读盘、不请求推理。已经透明的图像不再提前加载不需要的抠图模型。颜色检查可复用生成缓存，避免为颜色调整重新运行 14B。

## 截图中的颜色错误

原始 RGB 已有手部黄绿色色块，不能归因于透明棋盘格或抠图。现将参考图已检测的手指关键点随前臂、手腕转换到每个条件帧，并使用 DWPose 风格的原生尺寸骨骼渲染；身体线条与编辑器展示分离，额外跟/趾节点仍先转成身体脚踝端点。

透明帧完成后再检查整段曝光。只有至少两个身体区域一致表明曝光异常，才应用有上下限的统一增益；不自动分别调整 RGB 通道，避免手臂遮挡和面积变化使肤色偏绿。不确定偏色在全部帧中标为“待复查”，原始图保留。

有可靠手部参考时，另外检查皮肤附近出现的原图外异常色相，用参考肤色和相邻正常肤色做小范围 RGB 修正。保留原有 Alpha、其他区域及修正前图片；有色手套等不适用时跳过。源图中常见的衣服颜色受保护。**颜色修正不证明手部形状或多余物体已经修复**，不能用肤色覆盖代替完整结构验收。

本例还发现首帧的紫蓝色深发偏绿。对可靠的紫蓝深发参考，增加局部 Lab 色度校验，保留明度、Alpha 和面部区域；其他发色或不可靠参考跳过。这不是通用语义分割，不宣称适用于所有发型。实测纠正前图和 `hair-quality.json` 保留，不把原始模型结果当作颜色已完全通过。

新缓存额外包含 `matte.png`、`color-consistency.json`、`hand-quality.json`、必要的 `before_hand_color_repair.png`。可复查修正像素、增益、跳过原因和不确定项。

对已完成结果做独立对照，不改原缓存、不调用 GPU：

```powershell
& .\.venv\Scripts\python.exe -m tools.review_animation_colors '某次已完成动画任务的完整目录'
```

对照输出在 `data/color-reviews`，包含修改前后手部放大图、重新打包的帧和报告。优先复用已有原始透明帧，避免重复调色。原始 AI 输出和用户保存的文件均不改写。

## 验证与边界

```powershell
& .\.venv\Scripts\python.exe -m unittest discover -s tests -p 'test_*.py'
& .\.venv\Scripts\python.exe -m tests.live_motion_refinement
```

界面检查覆盖真实拖关节、只改当前帧、完整播放八个关键帧、人物示意/骨骼切换、当前帧标记和无模型事件时持续计时；使用本机测试参考，其他电脑需更换脚本输入。

模型验证使用同一个已保存任务的参考、种子、20 步和姿态输入，仅改变 CFG：

```powershell
& .\.venv\Scripts\python.exe -m tests.live_guidance_comparison '本机已完成的 Animate 测试任务目录'
```

该检查真实调用本机 14B，消耗 GPU 时间；首次需要启动本地引擎。开发与旧软件代码可以隔离，实际推理仍共用一套 ComfyUI 队列和硬件，同时生成会排队等待，不覆盖其他客户端任务。具体视觉结果与耗时见 [验证记录](VALIDATION.md)。
